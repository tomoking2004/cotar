## 1. 最優先：これだけは答えられるようにする

### 1分で説明してください

視覚言語モデルは，答えの正しさだけを目標に学習されるので，内部表現がどうあるべきかは学習の目標に入っていません．Wani らは，画像を少し加工すると，答えが同じでも内部表現が大きく変わる場合があると報告しました．人間なら，画像が加工されても同じ手順で答えを導くと考えられます．そこで，答えに至る手順が同じ質問どうしの内部表現を近づけ，違う質問どうしを遠ざける損失を，通常の学習に足しました．手順は，GQA というデータセットに付いている functional program の，操作の名前の並びで判定します．結果は三つです．手順の情報は内部表現から読み取りやすくなりました．しかし正解率はほとんど変わらず，答えが内部表現に依存する度合いはむしろ下がりました．手順の情報は内部表現に表れたが，答えの生成には十分に使われていない，と考えています．

### 言ってはいけない言い方

次の言い方は，測った範囲を超える．右の言い方に替える．

| 言わない | 言う |
| --- | --- |
| モデルは手順の情報を使っていない | 答えが $\boldsymbol{h}$ に依存する度合いが下がった．十分には使われていないと考えられる |
| 正解率に差は無い | 差の向きは決められなかった．低下は最大でも 1.81 ポイント |
| 整合で内部表現が頑健になった／動きにくくなった | 別の画像に替えたときの動きに対する比は小さくなった．動き自体は大きくなった |
| モデルが手順を理解した／推論能力を獲得した | 手順を見分けられる情報が内部表現に表れた |
| 視覚言語モデルでは一般に… | 1つのモデル，1つのデータセットでの結果では… |
| 署名は人間の解き方そのものだ | 署名は本研究が手順の代わりに使った形式で，それが最良かは検証していない |

### この研究の貢献は何ですか

内部表現から情報が読み取れることと，その情報が答えの生成に使われることは別だ，という点を，情報を明示的に作り込んだ場合について示したことです．正解率をほとんど損なわずに手順の情報を読み取りやすくできましたが，それでも答えが内部表現に依存する度合いは上がらず，下がりました．

補足：読み取れることと使われることの区別そのものは，既に知られている（Elazar らは，既にある性質を表現から除いて，モデルの予測への影響を見た）．本研究は逆に，損失で性質を足した場合を見た．

### 正解率が上がらなかったのなら，この手法に意味はあるのですか

正解率を上げる手法としては，今回の形では効果がありませんでした．わかったのは，内部表現に手順の情報を持たせるだけでは足りず，それを答えの生成に使わせる工夫が要る，ということです．内部表現の整合で性能を上げようとする研究にとって，読み取り精度が上がったことを「使えるようになった」と読んではいけない，という注意になると考えています．

### なぜ正解率は上がらなかったのですか

はっきりした原因は特定できていません．手がかりは二つあります．一つは，相対感度の結果で，答えが $\boldsymbol{h}$ に依存する度合いが下がっていることです．手順の情報を載せても，答えの生成がそこを以前ほど読んでいません．もう一つは，モデルが答えを間違えた質問でも，$\boldsymbol{h}$ から署名は高い精度で読み取れることです（提案手法で 96.4%）．手順の種類は内部表現に表れているのに答えを間違えているので，誤りは別のところで起きている可能性があります．どちらも説明の候補で，確かめてはいません．

### 相対感度とは何ですか

第16層の $\boldsymbol{h}$ を少し動かしたとき，最終層のベクトルが，答えの語を選び分ける向きにどれだけ動くかを表す量です．$\boldsymbol{h}$ を，最も効く向きに自分の長さの1%動かすと，最終層のベクトルがその向きに自分の長さの何%動くか，と読みます．baseline の8本での 0.40 は，1%動かすと最大で 0.40%動く，という意味です．大きいほど，答えの選択が $\boldsymbol{h}$ に強く依存しています．

### 何を，どのように1%動かすのですか

動かすのは $\boldsymbol{h}$，つまり第16層の，入力の末尾の位置にある 960 個の数値です．これに，$\boldsymbol{h}$ の長さの1%の長さを持つ小さなベクトルを足す，という変化を考えます．足す向きは，最終層のベクトルを「答えを決める方向」に最も大きく動かす向きです．ただし，実際に足してモデルを計算し直したのではありません．「足したらどれだけ動くか」を，微分で求めています．

補足：ほかの位置（画像や質問文の位置）の第16層のベクトルは動かさない，という前提の量である．微分なので，ごく小さな変化についての一次近似にあたる．

### 実際に動かして確かめたのですか

いいえ．有限の大きさで実際に動かして，最終層や答えの変化を見る実験はしていません．相対感度は，微分（勾配）から計算した量です．そのため，ごく小さな変化についての一次近似であり，大きく動かしたときに同じ割合で動くとは限りません．

### 「何%動く」は，何に対する%ですか

$\boldsymbol{h}$ の変化は，$\boldsymbol{h}$ 自身の長さ（ノルム）に対する割合です．最終層のベクトルの変化は，「答えを決める方向」の成分がどれだけ変わったかを，最終層のベクトル自身の長さに対する割合で表します．答えそのものが何%変わる，という意味ではありません．

### 「最も効く向き」とは何ですか

$\boldsymbol{h}$ は 960 次元なので，同じ1%でも，どの向きに動かすかで最終層の動きは変わります．その中で，最終層のベクトルを「答えを決める方向」へ最も大きく動かす向きが，微分で得られる勾配の向きです．相対感度は，その向きに動かした場合の値なので，上限にあたります．ほかの向きに動かせば，動きはこれより小さくなります．

補足：この向きは，問ごと，「答えを決める方向」1本ごとに違う．それぞれで値を出してから平均している．

### 「答えを決める方向」とは何ですか．横軸の本数は何ですか

出力層は，最終層のベクトルに重み行列を掛けて，各トークンのスコアを出します．重み行列の1行が1つのトークンに対応します．評価用データの正解の答えの，最初のトークンにあたる 1,085 行を取り出し，主成分分析をしました．上位の主成分は，答えの候補どうしのスコアの差が最もつきやすい向きです．横軸の 8本・32本・128本は，上位から何本の主成分を使ったかです．

補足：主成分分析の前に，1,085 行の平均を引く．全部の候補に共通する成分は，どの候補のスコアも同じだけ動かすので，候補の選び分けに効かないからである．

### 相対感度はどう計算したのですか

第16層の $\boldsymbol{h}$ から最終層のベクトル $\boldsymbol{r}$ までの計算を，一次近似します．$\boldsymbol{r}$ と，答えを選び分ける向き $\boldsymbol{u}$ との内積を作り，それを $\boldsymbol{h}$ で微分します．この勾配の長さが，$\boldsymbol{h}$ を動かしたとき $\boldsymbol{r}$ が $\boldsymbol{u}$ の向きにどれだけ動くかを表します．これに $\boldsymbol{h}$ の長さを掛け，$\boldsymbol{r}$ の長さで割って，割合に直します．評価用データの 64問と，$m$ 本の向きのすべての組で平均しました（設計と実装「相対感度」）．

### 相対感度が下がったことから，手順の情報が使われていないと言えるのですか

「使われていない」とまでは言えません．言えるのは，答えが $\boldsymbol{h}$ に依存する度合いが2割前後下がった，までです．0 になったのではありません．また，これは一次近似の量なので，一次近似で捉えられない経路までは否定できません．読み取りやすさが大きく上がったのに，依存する度合いは上がらず下がった，という組み合わせから，「十分には使われていない」と考えています．

### なぜ依存する度合いが下がったのですか

仕組みは特定できていません．ablation では下がらないので，同じ位置に対照学習の項を足しただけでは起きず，署名というラベルの意味が関わっています．

補足：説明の候補は，後ろの16層が画像や質問文の位置を注意で直接参照できるので，末尾のベクトルが手順ごとに組み替えられた分，答えに要る情報をほかの位置から読むようになった，というものである．確かめてはいない．

### 読み取り精度とは何ですか．どう測ったのですか

$\boldsymbol{h}$ だけを入力にして署名を当てる線形の分類器を作り，その正解率を読み取り精度と呼んでいます．評価用データのうち，10問以上ある署名の 10,990 問・145 種を使い，約半分で分類器を学習し，残りで採点しました．分類器は重み行列と切片だけの1層です．モデル本体は動かしません（設計と実装「読み取り精度」）．

### 整合損失は署名を分けるように学習するのだから，読み取り精度が上がるのは当たり前ではないですか

上がる向きは，損失の定義から予想できます．確かめたのは次の三つです．一つ目，ablation では上がらないので，対照学習の項を足しただけでは起きません．二つ目，質問文の語だけで見分けた場合の 69.7% を上回るので，質問文に現れる語では説明できません．三つ目，損失が教えていない情報まで読み取りやすくなっています．

補足（三つ目）：損失が教えるのは「署名が同じか違うか」だけである．そこで，署名に含まれる操作の種類を当てる分類器を，学習に使った署名と採点に使う署名が重ならないように分けて作った．46 種の操作をすべて当てた問の割合は，baseline 36.3% から提案手法 44.5% に上がった（ablation は 32.7%）．

### ablation とは何ですか．なぜ要るのですか

整合損失は同じ強さで掛けますが，誰と誰を近づけるかを，手順と無関係にした群です．バッチの中で署名のラベルを無作為に並べ替えます．提案手法が baseline と違うだけでは，対照学習の項を足したこと自体の効果かもしれません．ablation とも違って初めて，署名の意味による効果だと言えます．

補足：この対照が示すのは「意味のあるラベルが要る」までである．そのラベルが署名でなければならないか（たとえば答えが yes/no かどうか，のような粗いラベルでも同じ結果になるか）は，確かめていない．

### 整合損失は具体的にどう計算するのですか

バッチ 32問の $\boldsymbol{h}$ を長さ1にそろえ，全部の組のコサイン類似度を出します．各質問について，ほかの31問との類似度を温度で割って指数を取り，足して対数を取ります．そこから，同じ署名の相手との類似度を温度で割ったものを引きます．これを 32問で平均したものが整合損失です．相手との類似度が上がり，ほかとの類似度が下がるほど小さくなります（設計と実装「整合損失」）．

### なぜ第16層なのですか

全32層の中間の一点として選びました．第16層が最良だと示したわけではありません．

補足：乱数種1つだけの試走で，第8層と第24層に掛けた場合も測った．読み取り精度は 95.4%・95.0% で，第16層の 95.6%（同じ乱数種）とほぼ同じ，正解率は 53.66・53.53 だった．乱数種が1つなので，差の判定はできない．相対感度は第16層でしか測っていない．

### なぜ入力の末尾の位置なのですか

言語モデルは，各位置が自分より前しか参照できない作りです．入力の末尾は，画像と質問文のすべてを参照できる位置で，しかも答えの最初のトークンがそこから選ばれます．手順の情報を載せれば，答えの決まり方に最も届きやすい位置だと考えました．

補足：ほかの位置や，複数の位置の平均は試していない．

### 正解率に差が無いと言えるのですか

「差が無い」とは言っていません．提案手法と baseline の差は平均 −0.06 ポイントで，95% 信頼区間は [−1.81, +1.70] です．0 を含むので，上がったとも下がったとも決められません．言えるのは，下がったとしても最大で 1.81 ポイント，までです．

補足：予稿は「正解率に有意な差はない」と書いている．同じ区間についての記述である．

## 2. 聞かれやすい質問

### Wani らの研究は何をしたのですか

視覚言語モデルの頑健性を，答えだけでなく内部表現でも評価した研究です．画像に，意味が変わらない範囲の加工（ずらす，回す，縮める，文字を重ねるなど）を施し，加工の前後で答えと内部表現を比べました．答えがほとんど変わらなくても，内部表現は変化することを示しています．

補足：変化が大きいのは文字の重ね書きで，幾何的な加工での変化量は小さい．彼らは最終層で，Qwen3-VL・LLaVA-OneVision・Gemma-3 を SEEDBench・MMMU・POPE で測っている．対処法は示しておらず，今後の課題としている．

### Wani らの問題を，この研究は解決したのですか

解決したとは言えません．Wani らに倣った尺度（別の画像に替えたときの動きに対する比）で見ると，提案手法の比は小さくなりました．しかし内部表現の動きそのものは，提案手法のほうが大きくなっています．比が下がったのは，分母のほうがもっと大きくなったからです．ですので，動きにくくなったとまでは言えません（ポスター 3.3）．

### functional program とは何ですか．本当に人間の手順なのですか

GQA の各質問に付いている，答えに至る道筋を操作の列で書いたものです．“What's the girl holding?” なら，女の子を選ぶ，持っている物へたどる，それが何かを答える，の3段です．

補足：GQA の原典は，これを人間の手順とは呼んでいない．「人間が行う視覚的推論を計算可能な操作の列で表現したもの」は本研究の見方である．人間が実際にこの手順で答えているかは，検証していない．

### なぜ「手順を獲得すれば正解率が上がる」と考えたのですか

手順が同じ質問は，対象の物体が違っても同じ進め方で解けます．内部表現が手順ごとにまとまっていれば，モデルは手順の情報を物体によらず共通に使って答えを作れるので，正確さが高まると期待しました．これは期待であって，結果としては正解率はほとんど変わりませんでした．

### なぜ対照学習（SupCon）なのですか

したいことが「同じ手順の表現を近づけ，違う手順の表現を遠ざける」で，これは，同じクラスの表現を近づけ違うクラスの表現を遠ざける supervised contrastive loss の形そのものだからです．画像分類でのクラスを，署名に置き換えて使いました．

補足：ほかの損失（たとえば署名を当てる分類の損失を足す形）とは比べていない．

### 整合損失を掛けるのは1本のベクトルだけですか．ほかの位置はどうなりますか

損失を直接掛けるのは，第16層の末尾の位置の1本だけです．画像や質問文の位置のベクトルには掛けません．ただしモデル全体を更新するので，その1本を変えるために，手前の層の重みは変わります．

補足：後ろの16層は，注意の仕組みで画像や質問文の位置を直接参照できる．末尾のベクトルに頼らなくても答えを作れる経路が残っていることになる．相対感度が下がったことの説明の候補だが，確かめてはいない．

### SupCon の原典と何が違うのですか

確かめてある違いは二つです．一つは，原典は表現を小さなネットワーク（射影）で写した先で損失を計算しますが，本研究は第16層のベクトルに直接掛けます．もう一つは，原典は温度を固定しますが，本研究は学習で動くパラメタにしました．

### なぜ射影を挟まないのですか

学習できる射影を挟むと，内部表現そのものを変えなくても，射影の側を変えるだけで損失を下げられてしまいます．それでは「内部表現に手順の情報を持たせたらどうなるか」を問えなくなるからです．

### 重み λ = 0.1 はどう決めたのですか

この一点に固定しました．ほかの値は試していません．λ を変えたときに読み取り精度と正解率がどう釣り合うかは，今後の課題です．

### 署名で，操作の対象（girl など）を捨てるのはなぜですか

対象まで一致を求めると，同じ手順とみなす対がほとんど同じ質問になり，内部表現が近いのは当たり前になるからです．捨てたので，同じ署名でも質問の中身と答えは違います．

### 推論のときにも functional program が要るのですか

要りません．署名を使うのは学習のときの整合損失だけです．学習後のモデルは，画像と質問文だけから，通常どおり答えを生成します．

### どんなモデルですか．なぜそれを選んだのですか

SmolVLM-500M-Instruct です．視覚エンコーダが SigLIP-B/16，言語モデルが SmolLM2-360M で，全体で約5億パラメタです．言語モデルは 32層，960 次元です．計算資源の都合で，GPU 1枚で3群 × 乱数種の学習を繰り返せる大きさを選びました．

### モデルのどこを学習したのですか．LoRA ですか

モデル全体を学習しました．視覚エンコーダも言語モデルも凍結せず，LoRA も使っていません．公開されている重みから始めて，全パラメタを学習率 $10^{-5}$ で更新しています．

### 学習の設定を教えてください

バッチは 32問，学習率は $10^{-5}$，更新は 29,441 回で1エポックです．最適化の手法は RAdamScheduleFree，勾配のノルムは 1.0 で打ち切ります．GPU は RTX 5090 が1枚で，1回の学習は約2時間53分です（設計と実装「学習の設定」）．

### 「942,116問から16署名 × 2問を抽出」とはどういうことですか

1回の更新に使う 32問の作り方です．署名を無作為に 16 種選び，それぞれの署名から2問ずつ引きます．こうすると，どの質問にも，同じ署名の相手がバッチの中に必ず1問います．次の更新では，署名も問も選び直します．これを 29,441 回繰り返します．

補足：942,116 問は，学習用の 943,000 問から，同じ署名の相手が1問も居ない 884 問を除いた数である．

### baseline も同じバッチで学習したのですか

はい．3群は，バッチの作り方も，問の順序も，学習の設定も同じです．違うのは整合損失を掛けるかどうかと，掛けるときに誰を相手にするかだけです．

### ablation の学習では何が起きたのですか

近づける相手が手順と無関係なので，損失を下げる方法が「全部の表現を同じ向きにそろえる」ことしか残りません．実際，ablation の $\boldsymbol{h}$ は，同じ署名の対でも違う署名の対でも，コサイン類似度の平均が 0.99 を超えました．評価用データでの整合損失は約 3.434 で，全部が同じ向きにそろったときの理論値 $\log 31 = 3.434$ と小数第3位まで一致します．

### それでも ablation の読み取り精度が 81% あるのはなぜですか

表現がほぼ同じ向きにそろっても，その向きと直交するわずかな成分が署名ごとに違っていれば，線形の分類器はそれを取り出せるからです．81% は baseline の 82.9% とほぼ同じで，通常の損失だけで保たれる水準だと読んでいます．表現どうしの近さと，そこから読み取れる情報の量は，別の量です．

### 乱数種は何を変えるのですか．3つで足りるのですか

学習で変わるのは，バッチにどの署名とどの問を引くかの順序と，ablation での並べ替えです．モデルは毎回同じ公開の重みから始めます．3つは多くありません．そのため，群の差は 95% 信頼区間で判定し，区間が 0 を含む場合は「差が無い」ではなく「向きを決められない」と読んでいます．

### 評価はどのデータで行ったのですか．学習データと重なっていませんか

GQA の `testdev_balanced` の 12,578 問です．学習・検証・評価の三つの分割のあいだで，質問も画像も重なりは 0 であることを数えて確かめました．評価に使う 398 枚の画像は，学習に一度も出ていません．

### 正解率 53.5% は低くないですか

ほかの手法との比較はしていません．値は，この軽量なモデルを，画像を分割せずに1枚 512×512 で入れ，1エポックだけ学習した条件でのものです．公式の評価プログラムの内訳では，答えを自由に述べる型の問の正解率が約 39%，それ以外の型の問の正解率が約 70% です．本研究で見たいのは3群の差で，3群は同じ条件にそろえてあります．

補足：このモデルの論文は，小さいモデルでは画像の分割が視覚タスクの性能を上げると述べている．本研究は末尾の位置を正確に求めるために分割を切っているので，推奨の設定での値ではない．分割を入れたときに同じ結果になるかは測っていない．

### 答えはどう生成して，どう採点したのですか

画像と質問文だけを入れ，1トークンずつ，最も確率の高いトークンを選んで生成しました．最大 16 トークンです．生成した文字列を小文字にして句読点を除き，空白を詰めてから，GQA が配っている公式の評価プログラムに渡しました．正解と一致した問の割合が正解率です．

### 評価用データで分類器を学習するのは，おかしくないですか

おかしくありません．測りたいのは「学習済みのモデルが出す $\boldsymbol{h}$ に，署名の情報が載っているか」です．モデル本体は評価用データを一度も学習に使っていません．分類器は評価用データの半分で学習し，残りの半分で採点するので，採点に使う問は分類器も見ていません．

### GQA の質問文は型から自動で作られています．署名は質問文の言い回しを見ているだけではないですか

その懸念があるので，質問文の語だけを入力にした同じ分類器と比べました．それは 69.7% で，$\boldsymbol{h}$ からの読み取り精度（baseline 82.9%，提案手法 95.9%）はこれを上回ります．さらに，質問文の先頭4語が同じ質問を，分類器の学習側と採点側に分かれないようにした場合でも，提案手法と baseline の差は 14.5 ポイントで，保たれました．

補足：質問文の語だけの分類器は，語の順序をほとんど使っていない．質問文から原理的に取れる情報の上限ではない．

### baseline でも 82.9% あります．もともと手順の情報は内部表現にあったのですか

はい，整合損失を掛けなくても，署名は線形に読み取れます（常に最も多い署名と答えた場合は 28.8%）．ただし表現どうしの近さで見ると，同じ署名の対と違う署名の対のコサイン類似度は 0.945 と 0.918 で，ほとんど差がありません．情報は取り出せるが，手順ごとにまとまってはいない，という状態でした．

### 提案手法で，同じ手順の内部表現は実際に近づいたのですか

相対的には近づきました．評価用データで見ると，同じ署名の対のコサイン類似度は 0.945 から 0.745 に，違う署名の対は 0.918 から 0.225 になりました．同じ署名の対の類似度そのものは下がっていますが，違う署名の対がそれ以上に下がったので，両者の差は大きく開いています．

補足：差を，ばらつきで割って比べられる形にした値（Cohen's d）は，baseline 0.82 から提案手法 2.38 になった．評価用データから抜いた 4,000 問で測った．

### 信頼区間はどう計算したのですか

同じ乱数種の2群は同じ問を同じ順序で学習しているので，乱数種ごとに差を取ります．その差の平均と標準偏差から，対応のある $t$ 検定と同じ枠組みで 95% 信頼区間を作りました．乱数種3つのときの係数は 4.303 です（設計と実装「群の差の判定」）．

補足：差が正規分布に従うという仮定は，確かめていない．

### なぜ答えの最初のトークンだけを見るのですか

答えは1トークンずつ生成され，2つ目以降は最初のトークンに続けて決まるからです．また，整合損失を掛けた末尾の位置は，ちょうど最初のトークンが選ばれる位置です．

### なぜ割合（無次元）にするのですか

整合損失は，$\boldsymbol{h}$ の長さも最終層のベクトルの長さも変えうるからです．長さが違うモデルどうしで，動きの大きさをそのまま比べることはできません．両方を「自分の長さに対する割合」に直せば，群のあいだで比べられます．

### 64問で足りるのですか

問数を 8・16・32・48・64 と増やしたときの値を並べて確かめました．相対感度の値そのものは 64問でもわずかに動いていますが，提案手法の低下の割合は，8本ではどの問数でも −24% から −30% の間にあり，低下の向きは問数によりません．

補足：64問は，評価用データの先頭の 64問である．

### 128本で差が不明瞭とはどういうことですか

提案手法の低下は，8本で −28.0%，32本で −21.6%，128本で −18.0% で，どれも3つの乱数種すべてで下がっています．ただし 95% 信頼区間は，8本と32本では 0 を含みませんが，128本では [−36.4, +0.3] で，わずかに 0 を含みます．そのため 128本は「不明瞭」と書きました．

### 何のための解析ですか

出発点だった Wani らの問題，つまり画像を加工すると内部表現が動くことに，整合が効いたかを確かめる解析です．意味を変えない加工なら，答えに至る手順は変わらないはずです．$\boldsymbol{h}$ が手順を表しているなら，加工で動きにくくなるはずだ，と考えました．

### どんな加工をしたのですか

Wani らが定めた種類と値に倣った 23 通りです．横方向のずらしが8通り，余白の付加と切り出しが8通り，縮小が1通り，縮小して余白で戻すものが1通り，±30° の回転が2通り，画像の左上の白い箱への重ね書きが3通り（指示文，無作為な文字列，何も書かない箱）です．評価用の全 12,578 問に適用しました（設計と実装「解析②」）．

### 「動きの比」とは何ですか

加工の前後での $\boldsymbol{h}$ のコサイン距離を，同じ質問に別の画像を付けたときのコサイン距離で割った値です．「画像をまるごと替えたときの動きを 100% としたとき，加工でどれだけ動くか」と読みます．baseline は 14.75%，提案手法は 9.92%，ablation は 20.95% です．

### なぜ距離そのものでなく比を使うのですか

内部表現の広がり方が群ごとに大きく違うからです．提案手法は違う手順の表現を遠ざけるので，第16層では表現全体が広がり，加工による距離も，別の画像に替えたときの距離も大きく出ます．そこで Wani らと同じく，基準となる動きに対する比で表しました．

### 比が小さくなったのに，なぜ「動きにくくなったとは言えない」のですか

距離そのものは，提案手法のほうが大きいからです．baseline に比べて，加工による距離は約3倍，別の画像に替えたときの距離は約5倍になりました．分母のほうが大きく伸びたので，比は下がりました．言えるのは「画像を替えたときの動きに比べて，加工による動きが小さくなった」までです．

補足：距離そのものも，表現の広がり方が違う群のあいだでは公平に比べられない．したがって「動きやすくなった」とも言わない．安定性の評価は，比で見るか距離で見るかに依る，が結論である．

### この結果はほかのモデルやデータセットでも成り立ちますか

わかりません．1つのモデル，1つのデータセット，1つの層，1つの λ での結果です．ほかのデータセットで試すには，署名を作るための functional program にあたる注釈が要ります．

### 今後は何をしますか

二つあります．一つは，手順の情報を答えの生成に使わせる工夫です．今回の結果から，内部表現に持たせるだけでは足りないとわかりました．もう一つは，結果の及ぶ範囲を確かめることです．λ を変える，掛ける層を変えて相対感度まで測る，署名の代わりに別のラベル（たとえば答えが yes/no かどうか）で整合して，結果が署名に固有かを確かめる，といった検証です．

## 3. 余裕があれば

### 署名が1か所だけ違う質問も「違う手順」として遠ざけるのですか

はい．署名が完全に一致するか否かの二値で扱うので，1段だけ違う署名どうしも，まったく違う署名どうしと同じように遠ざけます．署名どうしの近さを使う形は，試していません．

### 計算のコストは増えますか

ほとんど増えません．整合損失は，通常の損失を計算する順伝播の途中で得られるベクトルを使い，足されるのは 32×32 の類似度の計算だけです．1回の学習時間は，3群とも約2時間53分でした．

### 温度はなぜ学習可能にしたのですか．最終的にいくつになりましたか

初期値は 0.07 で，学習後は提案手法で約 0.064，ablation で約 0.071 でした．大きくは動いていません．

補足：学習可能にしたのはこちらで決めた設定で，固定した場合とは比べていない．

### 署名を均等に選ぶと，データの分布が変わりませんか

変わります．問の少ない署名の問は繰り返し使われ，問の多い署名の問は一部しか使われません．一度でも学習に出る問は，粗い見積もりで多くても全体の約 41% です．ただし，このバッチの作り方は3群で共通なので，群の比較には影響しません．評価は自然な分布のまま行います．

### なぜ1エポックなのですか

この設定に固定しました．エポックを増やした場合は測っていません．

補足：学習の終わりに，学習用データの先頭 2,048 問と検証用データの先頭 2,048 問で通常の損失を測っている（提案手法・乱数種 42 で 0.426 と 0.447）．

### 追加学習をする前のモデルの正解率はいくつですか

測った記録がありません．比較の基準は，同じ条件で整合損失を掛けずに学習した baseline です．

### 珍しい手順の質問では効果があったのではないですか

見ましたが，効果は確認できませんでした．評価用の質問を，その署名が学習用データに現れた回数で5つの層に分けて正解率を比べました．どの層でも，提案手法と baseline の差の信頼区間は 0 を含みます．

補足：回数は学習用データの全 943,000 問で数えた．1〜10 回しか現れない署名の層（320 問）では，3つの乱数種すべてで提案手法が下回った（差 −2.50 ポイント）が，区間は [−6.61, +1.61] で 0 を含む．

### $\boldsymbol{h}$ を壊して答えが変わるかを見れば，使われているか直接わかるのではないですか

その実験はしていません．言語モデルでは，ある注意層を除くと，別の層がそれを補う現象（自己修復）が報告されています（McGrath ら）．壊しても答えが変わらないことは，そこが使われていないことを意味しないので，この方法は採りませんでした．

### 相対感度は既存の指標ですか

指標としては本研究で定義しました．層のあいだの計算をヤコビ行列で一次近似して，出力側の向きを途中の層に引き戻す考え方は，既存の研究（Gurnee ら）から借りています．

### Wani らの測り方と同じですか

指標の形は同じですが，違う点があります．分母を，質問文を固定して画像だけを替えたときの距離にしました．Wani らは最終層で測りますが，本研究は整合を掛けた第16層を主に見ています．重ね書きの指示文は，GQA に選択肢が無いので，「Answer is yes」か「Answer is no」に固定しました．答えは選択肢から選ぶのではなく，生成したものを使います．

補足：分母を変えた理由は，整合損失が質問どうしの配置を作り変えるからである．質問まで替えると，画像の影響ではなく，その作り変えを測ってしまう．Wani らの形の分母でも測ってあり，並び順（提案手法 < baseline < ablation）は同じだった．

### 答えが変わった割合は，どう数えたのですか

問1つと加工1つを1組として，加工の前後で生成した答えが変わった組の割合です．12,578 問 × 23 通りの組について数えました．23 通りを合わせると3群とも約 16% で，どの群の差も信頼区間が 0 を含みます．

補足：加工の種類ごとに見ると，文字のある重ね書き2種では提案手法が baseline より少し低い（−0.87・−0.96 ポイント，区間は 0 を含まない）．ただし ablation も同じくらい低く，提案手法と ablation の差は区間が 0 を含むので，署名の効果とは言えない．

### なぜこの解析だけ乱数種が5つなのですか

乱数種3つで測った時点では，提案手法と baseline の比の差は3つとも同じ向きでしたが，信頼区間が 0 を含みました．向きを決めるために乱数種を2つ足しました．足す数は，追加の結果を見る前に決めています．5つでの差は −4.82 ポイント，区間は [−7.87, −1.77] です．

### 最終層ではどうでしたか

最終層（第32層）の比では，提案手法と baseline の差の信頼区間は 0 を含みます（−0.12 ポイント，[−0.51, +0.27]）．23 通りを合わせて見るかぎり，第16層で見えた比の差は，最終層の比と答えには見えていません．

### 署名は，手順の表し方として適切ですか

最良かどうかは検証していません．操作の名前の並びだけを見るので，対象の違いや，署名どうしの近さは無視しています．

補足：GQA には，含意関係にある質問の対（互いに矛盾しない答えが求められる対）が定義されている．検証用データのその対 20,867 組のうち，52.1% は署名が異なる．署名が捉えているものと，この関係が捉えているものは別である．

### 予稿とポスターで違うところはありますか

主な結果は同じです．予稿は baseline と提案手法の2群だけを載せ，ポスターは ablation を足した3群を載せています．画像を加工する解析（ポスター 3.3）は予稿の提出後に行ったもので，予稿にはありません．相対感度は，予稿が 8本と 128本，ポスターが 8本・32本・128本です．
