# 発表資料の原則

`presentations/` の全資料（ゼミのスライド・学会のポスター）に適用する．**決定はこの文書が唯一の在処であり，各 pptx はこれを実装する**——食い違ったら，どちらが正しいかをここで決めてから直す．学会が定めるもの（講演番号・ボードの寸法・発表形式．[abstract.md](abstract.md)）は学会の定めが優先する．何を主張するか・数値をどう出すかは [.claude/context-philosophy.md](../.claude/context-philosophy.md) の領分で，予稿の組版は [papers/principles.md](../papers/principles.md) の領分である．本原則は，それらを**聴き手の前に置く形**だけを扱う．

節は，資料を作るときにぶつかる問いの順に並べてある——何を言うか（§1），どの順で言うか（§2），どう書くか（§3），どう見せるか（§4），ファイルをどう扱うか（§5），そして確定前に何を確かめるか（§6）．

**見せ方の方法はスキルが持ち，この資料での決定は本書が持つ．** 色の検証や部品の編集の方法はスキルの領分で，本書には写さない．本書に書くのは，決めた値と，スキルの既定と違う決定だけである．スキルの既定はスライドや Web を想定したものが多く，学会のポスターにそのまま当てない．食い違ったら，学会の定め，教授の指摘，本書，スキルの既定の順に優先する．

| スキル | 使う場面 | 本書が上書きする既定 |
| --- | --- | --- |
| frontend-design:frontend-design | 見た目を批評するときの観点 | 既定の見た目の一覧（題の帯，見出しの線，淡い枠は学会ポスターの普通の形なので避けない），独自の見た目を打ち出す勧め，Web の要件 |
| dataviz | グラフを作るとき．形の選び方と色の検証（§4，§6） | 棒に添える値の数（§4），文字に群の色を着せないこと（§3），hover の層と表の切替（印刷に無い） |
| anthropic-skills:pptx | 部品の編集と検証（§5，§6） | Design Ideas（帯や見出しの線を禁じる項，配色・図標・文字の大きさの表・安全な書体の一覧．雛形と §3・§4 が決める），新規の作成に pptxgenjs を使うこと（§5） |

確定前の走査（§6）では，design:design-critique で批評を受け，design:accessibility-review でコントラストを測り（印刷物なので，操作と読み上げの項は対象にしない），design:design-system で本書の値のほかが部品に無いかを監査する．pptx-deck:create-deck は使わない——ゼミは研究室の雛形，学会のポスターは本書で組む．

## 1. 中身——研究文書と同じことを，同じ強さで言う

**資料は研究文書の要約であって，新しい主張の置き場ではない．** 研究文書（[.claude/context.md](../.claude/context.md)）に無いことは書かない．研究文書が「向きを決められない」と書いたものを「高めた」と書かない．

- **値は `analyses/` から取り，表示の桁で丸めたものだけを載せる．** 研究文書の文から値を写さない（研究文書もまた要約である）．差は丸める前の値から計算する．載せた値はすべて，§6 の照合で出どころを言えること．
- **主張の強さを，研究文書の語で保つ．** 区間が 0 を含む差は「向きを決められない」，相対感度の低下は「依存する度合いが下がる」（「使っていない」ではない．研究文書の「頼る」は口語的なので資料では使わない．教授の指摘，2026-11-09），帰属できない効果は「…には帰せない」．字数を詰めるために強さを変えない——短くするなら，主張を減らす．
- **区間が 0 を含み，両端とも ±2pt 以内の差は「ほとんど変わらない」と書く．** 正解率（[−1.81, +1.70]pt）や答えが変わった問の割合（[−0.60, +0.32]pt）で聴き手に要るのは，ほとんど変わらないことである．「群の差の向きは決められず」は初見で意味が伝わらない（教授の指摘，2026-11-09）．研究文書も正解率を「ほとんど動かない」と書く．結果の見出しでは「3群でほとんど同じ」とする．それより広い区間が 0 を含むときは向きを決めず，ポスターでは「差ははっきりしない」と書く．
- **同じ基準を全章に当てる．** ある章で「向きを決められない」と書く条件（区間が 0 を含む）の差を，別の章で「低下」とだけ書かない．範囲で言う値の端が区間で 0 を含むなら，そう添える．限定のある文（「幾何的な加工では」）から限定を落とさず，整合の前から成り立っていること（「読み取れる」）を，整合の効果のように書かない．
- **指標ごとに，測った問の範囲を書く．** 指標によって問の数や抽出が違うなら，評価の問数だけを書いて全指標に掛かるように見せない．
- **測った量は，測った名で呼ぶ．** 「安定性」「頑健性」のような概念名は，それを何で代表させたか（比・距離）と組で出す．ポスターでは，本研究の測った量の結果と結論に概念名を使わず，測った向きで言う（「加工で 𝒉 が動きにくくなった」．「安定性　ってなんですか？」教授の指摘，2026-11-09）．比を見せて距離を載せないなら，比が示したことだけを結論にし，分母の変化をその前に添える——群ごとに分母が違う比の低下は，動きにくくなったことを意味しない．
- **同じものを二通りに呼ばない．** 研究文書の語（整合・タスク署名・読み取り精度・相対感度・baseline／proposal／ablation）を資料の全体で通す．言い換え（「揃えた」「重み」）は，同じものが別のものに見える．
- **スライドだけで全部が伝わるようにする．** 発表者のメモは，本人も聴き手も読まない．だからメモは空にしておく——メモにしか無い情報は，伝わらない情報である．定義，理由，出典（「Wani らと同じ計算」のような），原典との違い，測る前に決めた読み方は，メモではなくスライドに置く．枚数は増やしてよい．本筋の理解に要らない細部（原典との設定の細かな違いのような）は，本編から外して補足資料（参考文献の後）に回す．
- **本編は，文ではなく短い語句で書く．** 一枚の主張を，短い語句の箇条書き・図・表で一目で分かる形にする．箇条はできるかぎり体言止めにする（「内部表現は変化」「正解率：ほぼ不変」）．対比は「A → B」「A ／ B」や表にし，文を連ねない．ポスターの結論は，専門外の人が読んで分かる一文にする．≠ のような記号で主張を言わない——「読み取れる ≠ 使われる」は，何を言いたいのか聴き手に伝わらなかった（教授の指摘，2026-11-06）．問いだけは問いの形で残す（§2）．ポスターでは手法の説明と目的の行も例外にせず，「〜を追加」「〜の確認」のように語句で閉じ，理由は「A → B」で書く．文のまま残すのは，問いと，キーアイデアと結論の一文だけである．文字を小さくして詰め込まない（§3 の大きさを守る）．
- **聴き手の判断に要らない語と細部は載せない．** 専門語（「双三次」のような）や原典の細部（「最も小さいモデルで」のような）は，聴き手が結論を判断するのに要らなければ削る．要るなら，その場で平易な語で言う．縮めすぎて理由が読めなくなった一文（「予測で文を変えると，群ごとに画像が変わる」）は，縮める前の因果に戻す．
- **除いて何も失われない要素は載せない．** 引用していない文献，誰も読まない注記，同じ値の二度目の掲載，作業の経緯（「〜を直した」「初案から変えた」）は置かない．
- **測った量は，何と何を比べた量かと，値の意味を，一文ずつ書く．** どの層・どの位置のどのベクトルどうしの距離か，比なら分子と分母が何で，値が大きい／小さいと何を意味するか（「比：加工による動きが，別の画像に替えたときの動きの何%か」）．別の作り方で測り直したなら，作り方そのものを名前にする（「平均を中央値に替える」）．似た量は，割り算の形で書き分ける（動きの比：「距離 ÷ 別の画像に替えたときの距離」，答えが変わった問の割合：「答えが変わった問 ÷ 全問」）——「比」と「割合」を名だけで並べると，どう違うのか曖昧に見える（教授の指摘，2026-11-09）．
- **群は群名で指す．** 「群」という語そのものを，実験設定で定義してから使う（「比べる3群：整合の有無と，整合に使う署名だけを変えて学習」．定義の無いまま「群ごとに」と書いて「群　って何？」と問われた．教授の指摘，2026-11-09）．「整合した群」のように二つの群に当てはまる言い方をしない（ablation も整合損失を掛ける）．一つなら proposal，二つなら「proposal と ablation」と書く．群の中身は，何をしたかが目に見える語で書く（ablation は「質問と対応しない署名（並べ替え）」．「署名を並べ替え（意味だけを除く）」では，何が除かれたのか伝わらない．本人の指摘，2026-11-08）．
- **分類と族は，どれがそれかを見せる．** 「幾何的な加工（5族）」のように分類に触れるなら，加工の表に区分の列を設けて示す．同じ操作の変種は，名前でも同じ族と分かるようにする（「指示文の重ね書き」「無作為な文字列の重ね書き」「文字なしの重ね書き」）．
- **比喩と内輪の語を使わない．** 「物差し」「探索的」のような語は，何をしたか・なぜそう読むかに置き換える（「族ごとの区間は8つ作るので，偶然0を外れうる」）．
- **借りたものには出典を付ける．** 他者の手法・指標・画像は，その場で番号か名前で引く．借りた尺度は，方法の行で借りたと書く（「Wani ら[1]の尺度：…」）——書かないと，勝手に考えた尺度と思われる（教授の指摘，2026-11-09）．参考文献は引いたものだけを，**初めて引いた順**に並べる．書式は [papers/principles.md §5](../papers/principles.md#5-相互参照と文献) に揃える（国際会議は「in Proc. {会議名}」，誌名と会議名は斜体，*et al.* は斜体）．

## 2. 構成——一枚に一つの主張を，論理の順に

**各スライド・各区画が言うことを一文で言えること．** 言えないなら，割るか削る．

- **題は内容を名指す．** 題と本文が別のことを言っていないか，本文の半分しか覆っていない題になっていないかを確かめる．同じ種類の題は同じ形にする（「〜の比（第16層）」のように，修飾の付け方まで揃える）．
- **前に出ていないものに触れない．** 今回の資料で新しく出す語・記号・指標は，使うより前のスライドで定義する．各スライドの主張は，それより前のスライドだけから導けること．
- **聴き手が既に知っている語は，定義し直さない．** 分野で通じる語（VLM・対照学習）と，研究で使い続けている語（署名・整合・baseline／proposal／ablation）は，そのまま使う——教授が知っているものを一から定義すると，枚数と文字が増えるだけである．学会のポスターは専門外の人も読むので，研究で使い続けている語は使う前に定義する．
- **流れは，問い→方法→結果→読み→次の手，の順に置く．** 読みは結果のすぐ後に置き，結論は最後にまとめて言い直す．結果の読み方（判定の表・区間の読み方）を独立したスライドにするのは，聴き手が初めて見る指標を出す発表だけで，進捗報告には置かない．
- **結果は，まず一枚の一覧で見せる．** 測った量（層・比と距離・回答）と群の比較を一つの表に並べ，区間が0を含まないものを太字にする．族ごと・作り方ごとの詳細は，一覧の後に，一覧に無いことだけを載せる．本筋で見せる群の比較は，問いに答えるもの（proposal − baseline と proposal − ablation）に絞る．
- **ゼミのスライドは，前回の結論から入る．** 前回からの差分（今回したこと）を最初に示し，「今後の目標」は研究文書の計画（§8）の順序と一致させる．
- **進捗報告は，聴き手の判断に要るところまでで止める．** 見積もりの式，乱数種ごとの値，本数を決めた理由のような裏付けは本編から外す（§1）．読み方の分岐の表は，結果のある回にも載せず，当てはまる読みだけを結果の後に言う．枚数は内容に見合う分にする．ポスターの作業の話と，研究文書の更新のような記録の作業は載せない——進捗報告は簡潔でよい（本人の指示，2026-11-06）．
- **ポスターは，離れて立った聴き手が上から読む．** 題と要点の帯だけで主張が伝わること．本文は章番号の順に読めるように置き（段組でも，行の組でもよい），章番号でその順を示す．講演番号は題の近くに大きく置く．題は和文だけにし，英題は載せない．
- **ポスターの要点の帯には，研究の問いとわかったことを，専門外の人に分かる語で置く．** 結果の数値だけを先に出すと，何の研究で何が要点かが分からず，その良し悪しを判断できない．アイデアは帯に置かない——一言に縮めると言い過ぎになり（「内部表現に明示的に持たせる」），目的と問いを欠いたアイデアでは，聴き手が置いて行かれる（教授の指摘，2026-11-09）．わかったことは，問いと並べて初めて意味が分かる．帯は聴き手が最初に読むので，それまでに説明していない語（「解き方」）を出さず，何のことか分かる語（「答えに至る手順」）と例で書く．研究文書の「解き方」は，ポスターの全体で「手順」と呼ぶ．
- **提案手法は，キーアイデア → 理由 → 方法 → 工夫 の順に置く．** 聴き手が理由の次に聞きたいのは「では，どうやって」である（教授の指摘，2026-11-09）．キーアイデアは「手順」でなく「答えに至る手順」と書く．理由は，キーアイデアをすると何が起き，それがなぜ掲げた問いに結びつくかだけを言う（「内部表現が，答えに至る手順を備える → 答えはこの内部表現を経て生成されるので，正解率の向上を期待」）．キーアイデアを言い直さない——「同じ手順を近づけ，違う手順を遠ざけるよう制約 →」はキーアイデアの復唱になる（本人の指摘，2026-11-09）．問いに答えない前置き（「物体が違っても手順が同じ質問は多数」）も置かない．強さは「備える」「期待」に留める．方法で整合損失を導入し，損失の式だけで終えずに，工夫の行で何を工夫したかを言う．式だけでは「結局何を工夫したの？」が伝わらない（教授の指摘，2026-11-09）．「学習を追加する」は実装である．
- **工夫の行には，借りた手法を素直に使う形から，どこを変えたかを書く．** 元の手法を知らない聴き手に向けて，元は何に使う手法かを先に言い，「本来こういう目的で使われるものを，こういうものに転用した」形にする（「画像分類で同じ種類の画像を近づける手法[3]を，答えに至る手順が同じ質問に転用」）．「近づける基準を，答えや物体ではなく，答えに至る手順にする」は，対照学習の本来の使われ方を知っている人にしか読めない（本人の指摘，2026-11-09）．元の形から意図して外した部品も工夫として書き，元の形を先に言ってから外したことと理由を添える（「元の手法は表現を小さなネットワークに通してから近づける → 通さず，𝒉（下図③）を直接近づける／通すと，𝒉 が変わらないまま，小さなネットワークの側だけで損失が下がりうるため」．研究文書 §3.3）．「元の手法が挟む小さなネットワーク」では何と何の間に挟むのかが分からず，「ネットワークの側」では VLM のことか小さなネットワークのことかが分からない（別の目の批評，2026-11-09）．元の手法の使われ方は原典の本文で確かめる——Khosla らの supervised contrastive learning は画像分類（ImageNet・CIFAR）に使われ，損失を射影（小さなネットワーク）の出力に掛け，射影を学習後に捨てる（原典 §3–4）．通常の学習との違い（答えだけでなく内部表現に目的を与えること）は，1章の「通常の学習の目的は，答えの正しさだけ」と方法の行が言うので，工夫には置かない．専門語（射影 head・クラス）は平易な語（小さなネットワーク・種類）に言い換える．
- **何を同じ手順とみなすか（タスク署名の判定）は，手法ではなく実験設定に置く．** それは実験の選んだ条件である（教授の指摘，2026-11-09）．手法の語は，呼んだ名のまま定義する（「タスク署名：…」．すぐ上で「タスク署名」と呼んで「署名：…」と説明すると違和感がある）．「操作の名前だけを並べた列」のような定義は初見では形が浮かばないので，例の実物を添える（「select: girl → relate: holding → query: name」の矢印の先に「select > relate > query」．本人の指摘，2026-11-08）．段を横に連ねるのは一行に収まるときだけにする——幅の狭い所では段の途中から次の行に折れる（「→ query: name」だけが次の行に落ちて美しくない．本人の指摘，2026-11-08）．program は原典（GQA の論文と配布データ）の書き方「操作: 対象」で書く——括弧を外して「select girl」と書くと，どこまでが操作でどこからが対象かが読めない（本人の指摘，2026-11-08）．
- **概念は手法（2章）で，具体は実験（3章）で説明する．** 本人の指摘である（2026-11-09）．手法の図は，質問の例に同じ手順か違う手順かの別（手順 A・B の名）だけを添え，何を同じとみなしたかの具体（署名と，その実物の例）は実験設定に置く．図の点の読み方は失わないように，図では手順を「手順 A」「手順 B」と名で呼び，実験設定でその名を具体に結ぶ（「→ select > relate > query：2章の図の手順 A（B は select > query）」）．図に署名を出すと，3.1 で定義する署名を定義より先に見せることになる．教授は「手順の判定」について「これは実験のところで説明する」と書いた（2026-11-09）．この項は，それを図にも及ぼしたものである．

- **図の例は，実際の写真と質問で，図の中で辻褄を合わせる．** 模式図より実際の写真のほうが学会発表らしい．VQA の図なので入力には質問文を置き，出力には具体的な答えを置く．例は評価データから選び，言うことを実測で確かめる（背景の図なら，モデルがどの乱数種でも正解し，加工で答えが変わらない問）．一つの問の量は乱数種で大きく揺れるので，確かめるときは全乱数種を見る．ただし，背景の図（先行研究の説明）には本研究で測った値を載せない——先行研究の結果と読まれる（「内部表現の動きは別の画像の42%」を Wani らの結果かと問われた．本人の指摘，2026-11-08）．確かめた値は研究文書と報告に置き，図は先行研究の方法の模式とする．質問を添えた画像にはその質問の答えが写っていること（ドレスの写っていない写真に “Who is wearing the dress?” を添えない）．矢印は実際の流れどおりに引く（内部表現は VLM の内部から取り出すもので，答えに直結するものでも，答えから出るものでもない）．同じ例を，背景の図・手順の例・手法の図・加工の例で通す．
- **背景の先行研究は，結果だけでなく，目的と方法を書き，簡単な図で示す．** 手法の前提になる例（「見つける・たどる・答える」のような手順）を説明なしに先に出さない．手法の語（タスク署名）は手法の中で導入し，背景に持ち込まない．先行研究の結果から何が言えるかは，問いにつながる形で書く（「答えだけでは，内部の様子は不明」では何を言いたいのか伝わらない）．仮説は問いの形で終え，それまでに出ていない観点を持ち込まない．
- **先行研究から問いへは，段を踏んで導く．** Wani らの結果（加工で答えは同じでも内部表現は変わる）→ 一方，人間は加工されても同じ手順を踏んで答えると考えられる → その手順を書き下したもの（GQA の functional program）が何かを説明する → 例 → 問い（このような手順を内部表現が獲得できれば，正解率は上がるか）．先行研究が示していないこと（11/8 の版の「人間が画像を見て答えに至るまでの手順の特徴を，内部表現は獲得できていない可能性」）を，その結果からの帰結のように書かない——Wani らが示したのは，答えが同じでも画像の変化が内部表現を動かすことまでである（教授の指摘，2026-11-09）．program は原典の定義で書く．GQA の論文は “a functional program which lists the series of reasoning steps needed to be performed to arrive at the answer”（§3）と書き，人間の手順とは書いていない．人間についての文は「考えられる」と本研究の見方として置き，program を「人間の推論手順を抽象化したもの」とは書かない．定義の文は，定義を先に，出どころを括弧で後に置く（「答えに至る推論の手順を，操作の列で書き下したもの（データセット GQA[2] の各質問に付属）」）——本人の案（2026-11-09）の「GQA[2] の各質問に付与されている，人間が答えに至る推論の手順を，操作の列で書き下したもの」のように出どころを前に置くと，読点で切れた「付与されている」が「手順」に掛かるのか「もの」に掛かるのかが読みにくい．本人は書き方を整えるよう求めた．本人の案の「人間が」は原典に無いので入れない（本人の判断，2026-11-09）．
- **結果は，目的 → 方法 → 結果 → 考察の順に書く．** わかったことを先に書かない．各グラフの前に，何のためにどう評価したかを書く——評価尺度は，採用した目的を言わないと聴き手に意味が伝わらない．各グラフの「結果」の見出しは，数値の大小や順位（「proposal が最小」「8・32本で proposal だけ低下」）ではなく，そこから分かること（「答えの 𝒉 への依存が低下」「3群でほとんど同じ」）にし，どの群がどれだけ動いたかは灰の小さな行に置く（「で、何がわかるの？と思われる」教授の指摘，2026-11-09）．聴き手は細かい数値の大小に興味がないので，区画の末尾に，結果から示唆されることを大きな文字で枠に置く．枠はどの節も同じ形にする——「考察」に続けて結論の根拠を一行で書き，大きな太字（スライドは赤，ポスターは緑．§3）で読みを置く．その大きな字に結果の言い直しを置かない（3.3 は「別の画像に比べた 𝒉 の動き（比）は小さくなったが，𝒉 が動きにくくなったとまでは言えない」までが読みである．前半を「加工による 𝒉 の動きは小さくなった」と書くと，後半と矛盾に読める——比の話であることを，結果の見出し（「比で見た 𝒉 の動きが縮小」）でも名指す．別の目の批評，2026-11-09）．根拠の行は，測った量と倍率で言う（「proposal は 𝒉 の動き自体が大きい（加工：約3倍，別の画像：約5倍）」）．「𝒉 の広がり自体が変化」のような語は，何が広がったのかが伝わらない（本人の指摘，2026-11-08）．研究文書が確かめていない因果（「対照学習が埋め込み空間を押し広げた」）は書かない．
- **評価尺度と比べる水準は，何を確かめるためか，入力が何かを書く．** 比べる水準を置くなら，見出し語は「対照」でなく「比較」とし（「対照」は専門外に通じない．教授の指摘，2026-11-09），その目的（「質問文を読むだけで当たる水準」）と，入力が内部表現でないこと（「質問文の語だけから署名を当てる同じ分類器」）を書く——書かないと，なぜその棒があるのか読み手に分からない（本人の指摘，2026-11-08）．横軸の量（方向の本数のような）は，それが何の数かを方法の中で名指す（「何が128本なのか」と読まれる）．
- **区間は，どの検定の区間かを書き，全ての結果に同じ形で添える．** 「乱数種を対にした t 検定（対応のある t 検定）の95%信頼区間」と書く．結果ごとに「baseline との差：値 [下限, 上限]」の形で載せ，一部の結果にだけ区間を載せない——載せた所と載せない所があると不揃いに見える（本人の指摘，2026-11-08）．区間が 0 を含む条件があるなら，灰の行にそう添える（「proposal だけ低下（128本は区間が 0 を含む）」）．見出しは分かることで書き（上），条件を見出しに並べない．
- **主筋の外の検証は，主筋との対比が分かるようにする．** 節の題は，その節が答える問いの形で中身を名指す（「3.2 手順の情報は内部表現に表れ，答えに使われるか」「3.3 画像を加工しても，内部表現は動きにくくなるか」．「追加の検証」としない）．何を入力にしたかの違いは，題の下の入力の行で言う（教授の指摘「何を入力にして，何にしたという対比が説明されていた方がよい」，2026-11-06）．題そのものを「元の画像を入力」「加工した画像を入力」の対比にしない——画像の加工は実験の一つであって，節を分ける軸ではない（本人の指摘，2026-11-08）．指標ごとに目的を添える．考察は結果の言い直しではなく，なぜそうなったと考えるかを書いたうえで結論を置く．
- **ポスターのまとめは，研究の要約→結果と考察の順に簡潔に書く．** 今後の展望と研究の意義は載せない（聞かれたら答える）．要点の帯が結論を言うので，まとめで帯の文を繰り返さない——同じ文が帯とまとめの両方にあると冗長に見える（本人の指摘，2026-11-08）．「結果」と「考察」は分けて書く．結果は測った指標ごとに，指標の名と，そこから分かったことを一行で（「読み取り精度：手順の情報が 𝒉 に表れた」）．数値の大小（「proposal だけ上昇」）は書かない——何が分かったのかが明確にならない（教授の指摘，2026-11-09）．考察は，結果から何が言えるかを，研究文書の結論の強さで（「内部表現の形は変わったが，答えの生成に使われるようになったとは言えない」）．指標の言い換え（「手順の情報：𝒉 から読み取りやすく」）を並べただけでは，結果とも考察ともつかない（本人の指摘，2026-11-08）．幅の狭い区画では，文の切れ目で改行して折る位置を決め，語の途中で折らない．注のような短い文も，各行が意味の切れ目で終わるように組む（「1モデル・1データセット・／第16層・𝜆 = 0.1での結果」ではなく「1モデル・1データセットでの結果／（整合は第16層，𝜆 = 0.1）」）．
- **予稿の流れ（はじめに→手法→実験→おわりに）を保つ．** 実験設定と結果は，一つの「実験」の章にまとめる．予稿の数値と食い違う値を載せない．予稿以後に足した結果に「予稿以後の測定」と書かない——聴き手の判断に要らない（教授の指摘，2026-11-09）．
- **実験設定では，何を同じ質問・違う質問とみなしたかと，比べる群の意味を書く．** 表は，何の表かを言う見出しの行（「比べる3群：整合の有無と，整合に使う署名だけを変えて学習」）と，読み方の行（「proposal が両方と違えば，手順（署名）による効果」）で挟む——説明の無い表は浮いて見える（教授の指摘，2026-11-09）．

## 3. 文字——大きく，少なく，一つの規則で

**読ませるのではなく，見て分かる量に絞る．** 一枚に収まらない説明は，メモへ回さず，スライドを割って一枚ずつ見せる．

- **大きさ．** スライドの本文は 24pt，二段目は 20pt に揃え（下限でもある），表と図と注記は 14pt 以上．A0 のポスターは 72／44／36／28／22／16pt の6種類だけを使う（題／講演番号・章の見出し・要点の帯・考察の結論／節の見出し・枠の結論／本文・図の数式／図表の文字・指標の説明・注記／参考文献）．隣どうしは約1.3倍で，読み分けられる差になる．間の大きさを足さず，どれかに寄せる——大きさの種類が増えると，一つ一つは正しくても，全体が雑然と見える．同じ役目の文字は同じ大きさにする．
- **ポスターの書体の太さと字間．** 本文は游ゴシック Medium にし（Regular は細く，離れると読みにくい），太字は合成でなく游ゴシックの Bold を当てる．游ゴシックの仮名は緩いので字間を詰める（題 1pt，要点の帯 0.6pt，本文と図表 0.4pt．PowerPoint には詰めの機能が無い）．
- **句読点は「，．」．** 箇条の末尾には句点を打たない．文として完結した段落にだけ打つ．
- **全角と半角．** 英数字は半角．和文の中の括弧は全角（），英文と数式の中は半角 ()．全角の英数字・記号（＝＋＜＞％）と半角カナは使わない．負号と引き算は −（U+2212），範囲は –（U+2013，「18–28%」），波ダッシュ「〜」は使わない．値や語句を並べる区切りは「／」，欧文の語の中（yes/no）は半角の「/」．
- **空白．** ラテン文字の語（baseline，GQA，Wani）と和文の間には半角スペースを1つ入れる．数を一つの語として立てるとき（「区間が 0 を含む」）も同じにする．数字と和文の間，数字と単位の間，単位と和文の間（「第16層」「1.7pt以内」「12,578問」），全角の括弧・句読点・記号の隣には入れない．数式の二項演算子（=，×，÷，−）は両側に1つずつ入れる．
- **略語は，初出で「正式名（略語）」と書き，以降は略語だけにする．** 「視覚言語モデル（VLM）」の形で，予稿（manuscript.tex の「視覚言語モデル（VLM）」）と揃える——「VLM（視覚言語モデル）」は逆である（本人の指摘，2026-11-09）．初出は資料の上から数える．ポスターでは要点の帯が箇条の定義より先に読まれるので，帯では略語を使わず正式名で書き（題も正式名である），1章の箇条で略語を導入する．データセットとモデルの名（GQA・SmolVLM）は固有名で，略語として開かない．図の「言語モデル部（LLM）」は，予稿の部品名に一般の呼び名を添えたもので（本人の指摘，2026-11-08．§2 の概要図の項），この項の略語の形には当たらない．
- **数値の書き方．** 比率は「%」，差は「pt」，区間は「[下限, 上限]」．4桁以上は3桁ごとに「,」．同じ量は全資料で同じ桁に丸める．
- **強調は，一枚に一つの結論にだけ使う．** スライドでは強調の赤を，その枚の結論か，聴き手の目を最初に向けたい一点だけに付ける．赤は proposal の群の色と同じなので，群の値にはその群の値にしか付けない．ポスターは一つの色相で組むので（§4），結論は色ではなく大きさと太さで示す——要点の帯の二つの見出し（問いとわかったこと）と考察の枠の読みを，緑の大きな太字にする．帯の二つは同じ色にそろえる（片方だけ墨だと不揃いに見える．本人の指摘，2026-11-08）．太字は見出しと，ポスターで要点を示す語に限り，段落全体を太字にしない．
- **測った量の名は，それと分かる形にする．** ポスターでは，指標の名（読み取り精度・正解率・相対感度・動きの比・答えが変わった問の割合）を，緑の地に白抜きの太字の札にする（前期公開期末のポスターの表の見出しと同じ扱い）．札はほかに使わない——札を見れば「これを測った」と一目で分かる（本人の指摘，2026-11-08）．新しい色相（一度は紫にした）で分けない——色数が増えてまとまりを失う．構造の見出し（結果・加工の例）は緑の字のままにする．
- **字下げは一つの規則にする．** 見出し語（目的・方法・比較・結果・考察・問い・例・加工の例，提案手法のキーアイデア・理由・方法・工夫）は緑の太字にし，その後はタブで本文の頭を揃え，続きの行もその頭に揃える（同じ「結果」が区画によって黒と緑になっていた．別の目の批評，2026-11-08）．一つの塊の中で頭の位置を一つにする（ポスターは2字の見出し語で 2.7cm，提案手法で 6.6cm）．見出し語の後を全角の空白で空けない——語の長さで頭がずれ，続きの行だけ一段深く見える（本人の指摘，2026-11-08）．項目と値の組（入力：，モデル：，正解率：）はコロンで続ける．
- **行は，意味の切れ目で折る．** 数と単位（「10問」），記号と助詞（「𝒉 を」），区間の両端は行で割らない．幅の狭いカードでは，一行ずつ段落を分けて折る位置を決め，自動の折り返しに任せない．
- **誤字を残さない．** 用語の揺れ（§1）・送り仮名・変換の誤り・表と本文の数値の不一致を，§6 の走査で確かめる．

- **教授に送った版から，見た目を不用意に変えない．** 教授に送ったポスターは 10/29・11/5・11/8・11/10 の4版で，どれも `tmp/professor/` にある．11/10 の版の組み（帯の問い，図の番号，3.1 の3列）は，11/8 の版への教授の指摘による改めである．組み（区画の位置，色，図の形）を改めるのは，教授か本人が求めたときだけにする．磨くときは，並べて同じポスターと分かる範囲（書体の太さ，字間，値の色，棒の幅，余白のずれ）に留める——組み直すと，教授が困惑する（本人の指摘，2026-11-07）．

- **見た目の差は，意味の差として読まれる．** 意味の無い差を作らない（Marshall らの聞き取りに，色の違いで別物と思ったという発言がある）——同じ役目の部品は同じ寸法（答えと正解の箱は 7.5 × 2.2cm）にし，𝒉 はどこでも同じ丸にし，VLM の枠と層はどの図でも同じ色と形にする．矢印の頭と線の種類は流れの種類ごとに一つとし，部品より目立たせない．段を順に並べる矢印は，前の段の文の終わりと次の段の写真のあいだの中央に置く——次の写真に接して置くと不自然に見える（本人の指摘，2026-11-08）．
- **一つの部品の塗りと線の両方に色を付けない**（伝わるデザイン）．モデルの入れ物と部品（VLM の枠・視覚エンコーダ・層・出力層）は灰色の地だけにし，線を引かない．入力と出力のデータ（質問文・答え・正解）は白地に線の箱にする——データとモデルを同じ灰にすると，どれがモデルか区別できない（本人の指摘，2026-11-08）．言語モデル部の囲みは灰の線だけで，地を塗らない．写真の縁だけは，白い背景の写真が紙に溶けないよう，淡い灰の 2.25pt を全ての写真に引く．写真の上の緑の枠には，芝の緑に沈まないよう白の縁を付ける．

- **ポスターは一つの色相で組む．** 使う色は白（地）・墨（文字）・緑とその濃淡・灰の四つで，緑以外の色相を足さない．出典は二つある．一つは本人の前期公開期末のポスター（[20260724_前期公開期末.pdf](20260724_前期公開期末.pdf)）で，緑・淡い緑・黒・白だけで組み，強調を太字と「→」で示している．本人はこれを美しいと評した（2026-11-08）．もう一つは配色の指針である．色は背景と文字を含めて4色ほどにし，テーマ色を決めて同じ規則で繰り返す（[伝わるデザイン](https://tsutawarudesign.com/miyasuku5.html)．UBC の指針も3–4色）．グラフは，注目する群を濃く鮮やかに，ほかを灰や同じ色相の淡い色にし，目立たせないデータに新しい色相を足さない（[Datawrapper](https://www.datawrapper.de/blog/emphasize-with-color-in-data-visualizations/)）．赤と緑の組み合わせは避ける（UBC，Wong 2011）．採らなかった指針もある：「強調には橙や水色を少量使う」「緑は黒と見分けにくく，強調に向かない」（[伝わるデザイン](https://tsutawarudesign.com/universal1.html)）——緑の字を強調に頼らず，結論は大きさと太さで示すことで応える（§3）．
- **ポスターの基調色は緑 `4A8C45`．** 前期公開期末の緑 `70AD47` のように明るい色が美しいが（本人の好み，2026-11-08．一度は `2E6B34` まで深くして全体が暗くなった），`70AD47` は白抜きの字とのコントラストが 2.7:1 で，大きな太字の基準 3:1 に届かない．そこで，届く範囲で明るい `4A8C45` にした——白抜きで 4.1:1，白地の緑の字で 4.1:1，淡い緑の地の緑の字で 3.4:1．緑の字は見出し・語句の見出し・結論など太字の大きな字だけに使う（本文の色にしない）．題の帯・章の線と見出し・語句の見出し・指標の札・表の線・番号・結論の字・proposal とそれが足すもの（第16層・𝒉・整合の点と矢印）に使い，淡い緑 `E2EFDA` を枠の地に使う．文字と図の主な線は `1F2421`，注記は `59625C`，図の入れ物は灰色の地 `F2F4F2`，層の棒とモデルの部品は `D5DAD6`，第16層の地は中間の緑 `A9D18E`（灰の層と ΔE 11.5），写真の縁と表の細線は `C4CBC5`，ベクトルの模式の濃淡は `E2EFDA`・`C5E0B4`・`8FBF78` と基調色にする．スライドは白地に黒の文字で，色は群の色と強調の赤だけにする．
- **ポスターの全区画を，12列の格子に載せる．** 外周 2cm，列の間 1.2cm（列の幅 8.475cm）．上の段は 6列 + 6列（1章・2章），下の段は 10列 + 2列（3章・4章）に分け，3章の 3.2 は6列（三つの指標は2列ずつ），3.3 は4列にする．3.1 も同じ縦の線に載せ，左から読む3列にする——同じ手順の判定は 1–3列，比べる3群（表）は 4–6列，学習と評価は 7–10列（3.3 の左端から）．区画の幅は中身の量に合わせ，窮屈な区画と空いた区画を同じ紙面に作らない．区画の左右の縁と，段の上下の縁を揃え，3.2 と 3.3 の結論の枠は上端も揃える——縁が揃うと，線で囲まなくてもまとまって見える．
- **区画は，線と余白で示す．** 章は上に太い緑の線を引き，その下に見出しを置く．面を塗るのは題の帯と，強調する枠と，指標の札（§3）だけにし，枠は線で囲まず，角を丸めず，淡い緑の地で示す．枠の種類を増やさない（点線・破線の枠，色違いの枠を使わない）．破線は「VLM を更新」のような，流れの種類が違う線と，前の手順の跡にだけ使う．図の線は，主な流れを 3pt，枠・細い流れ・引出線を 2.25pt，proposal が足す流れを 4.5pt にする——A0 では 1.5pt 以下の線は文字に負けて見えない．

- **表は，見出しの行で量と単位を言う．** 同じ資料の表は同じ表の様式（表スタイル）を使う．ポスターの表は横線だけで組み，縦線と地の色を使わない（上の線を太く，見出しの下と末尾の線を細く，行の間を灰色の細線に）．
- **余白は一つの規則で取る．** スライドの本文は，どのスライドでも同じ高さ（上端から 1.8 インチ）から始める．本文の塊（文・表・図）どうしの間隔は，書き出した画像で測って 0.25 インチに揃える——空きすぎも詰まりも，この規則から外れた所に出る．段落の前の間隔も一つにする（一段目 9pt，二段目 3pt，塊の先頭は 0）．中身の少ないスライドは上に詰めて下を空け，塊の間に間隔を足して埋めない．
- **ポスターの見出しの前後は，一つの規則で空ける．** 章の線から最初の行まで 2.55cm，節の見出し（3.2・3.3）の上は前の塊から 1.2cm，節の見出しと入力の行の下は 0.6cm 空けて中身を置く．節の表と注は，節の題の行ではなく本文の一行目の高さから始める．3.1 の行は，3.2・3.3 の見出しとの間に灰の細線を引いて閉じる——閉じないと，3.1 の注が 3.3 の頭に見える（別の目の批評で2度指摘，2026-11-08）．見出しを前の塊に詰めない——「3.」「3.1」「3.2」が詰まって見える一方で「1.」「2.」に空きがあると，紙面の釣り合いが悪い（本人の指摘，2026-11-08）．
- **余白で区切る．** 区画どうしの間隔は揃え，詰まった所と空いた所を作らない．短い行が続いて区画の右に空きが出るなら，二段に組むか，説明の例をその空きに置いて埋める．1章の上部は用語の箇条と Wani らの研究を左右に並べ，2章はタスク署名の定義の右にその例を置いた．空いた右上と詰まった3章が同じ紙面にあると釣り合いが悪い（本人の指摘，2026-11-08）．文字が枠からはみ出す，枠どうしが重なる，一字だけの行が出る，語や数値と単位が行を割れる——を残さない．スライドの端から 0.5 インチ，ポスターの端から 2cm は文字を置かない．
- **一般の体裁から外れない．** ゼミのスライドは研究室の雛形（表紙・題の位置・書体・箇条の形）に従う．学会のポスターは，題・著者・所属を上に，本文を段組に，参考文献を末尾に置く．ボード（横 180cm × 縦 90cm）に収まる判（A0 横）にする．

## 5. ファイル——部品を保ち，開き直して確かめる

**既存のファイルは，書式ごと作り直さない．** 直すのは部品（XML）の水準で，文字を差し替えるのを基本とする．組み方そのものを改めるときはスライドの部品を書き直してよいが，グラフ・埋め込みのブック・画像の部品は残し，文の変更は差分で確かめる．

- **python-pptx で書き直さない．** 読む・確かめるのには使ってよい．スライドの追加・削除も部品の水準で行い，`presentation.xml`・その rels・`[Content_Types].xml`・`docProps/app.xml`（枚数と題）を一緒に直す．`app.xml` は `<Slides>`，`HeadingPairs` の題の数，`TitlesOfParts` の `vt:vector size` と実際の要素数の四つを揃える——`size` が要素数と一つ違うだけで PowerPoint は開くのを拒む（0x80070570）が，python-pptx もスキーマの検証もこれを通す．python-pptx が書くと壊れる既知の点——チャートの一つの文字指定に `a:latin` が二つ入る，`c:axId`・`c:crossAx` が負になる——を持ち込まない．
- **作業の経緯をファイルに残さない．** 発表者のメモとコメントにも書かない．文書のプロパティの作成者は本人にする．
- **文字の言語は日本語（`ja-JP`）にし，テーマの東アジアの書体に日本語の書体を当てる．** スライドは研究室の雛形の書体（游明朝・游ゴシック），ポスターは游ゴシックである．
- **参照されない部品を残さない．** 消したスライド・画像・チャートの部品と関係（rels）は一緒に消す．
- **書いたら，保存したファイルを開き直して確かめる**（§6）．
- **PDF を本人の環境の外（LibreOffice など）で書き出すときは，日本語の文字に日本語の書体が当たるようにする．** 游明朝・游ゴシックが無い環境では，日本語版の代替（IPAex 明朝・IPAex ゴシックなど）を書体の別名として当てる．PDF は，直した回のうちに最終のファイルから書き出し直す．
- **更新したら，そのたびにファイルを本人に送る**（[CLAUDE.md](../CLAUDE.md)）．
- **ポスターの 3.3 節（頑健性）の値と読みは，[scripts/update_poster.py](../scripts/update_poster.py) が書く．** `analyses/probe-drift.json` から研究文書 §8.1 の表の行を選び，動きの比のグラフと，名前の付いた段落（`Drift result`・`Drift answers`・`Drift discussion`，`Summary`・`Summary discussion` の末尾）だけを部品の水準で書き換える．図形の名前を変えない．手で書き換えた値は，次に走らせたときに戻る．研究文書の更新が先である（§1）．

## 6. 確定前の走査

**綺麗に見えることは根拠にならない．以下がすべて期待値を返してから確定する．**

1. **値の照合**：資料に載る数値をすべて抜き出し，`analyses/*.json`（問ごとの値は `analyses/probe-drift.pt`）から計算し直した値と一致させる．一致しない値・出どころを言えない値が 0 件．ポスターの 3.3 節は，`scripts/update_poster.py` が「nothing to change」を返すこと．
2. **部品の検証**：pptx スキルの `validate.py`（元の資料があれば `--original` を渡す）が合格し，dotnet のある機では Open XML SDK（DocumentFormat.OpenXml 3.1.0）の検証も 0 件．python-pptx で開き直せる．参照されない部品が 0 件．`[Content_Types].xml` に宣言だけ残った部品が 0 件．PowerPoint のある機では，PowerPoint で実際に開いて確かめる——スキーマと python-pptx が通っても開けないファイルがある．研究室機のように PowerPoint が無い機で作ったら，開けることを確かめていないと報告する．
3. **書体**：書き出した PDF に埋め込まれた書体に，名前に SC・TC を含むもの（中国語の書体）が 0 件．
4. **文字の走査**（0 件）：「、。」，全角英数字・半角カナ，全角の ＝＋＜＞％，「〜」，ハイフンの負号（数字の前の `-`），ラテン文字の語と和文のあいだの空白の欠け．
5. **メモが空**：発表者のメモに文字が 0 件．
6. **定義の順序**：各スライドで初めて出る語・記号・群名・指標を列挙し，聴き手が既に知っている語（§2）を除いて，それより前のスライドに定義の無いものが 0 件．
7. **余白を測る**：書き出した画像から，各スライドの本文の始まりの高さと塊どうしの間隔を測り，§4 の値から外れたものが 0 件．ポスターは，使っている文字の大きさが §3 の6種類だけで，並べたグラフの底の線の高さが揃っていること．図形の比も部品の寸法から測り，§4 の上限を超える入れ物と箱が 0 件，表示の比が元の比から 1% 以上ずれた写真が 0 件，解像度が 100dpi を切る写真が 0 件であること．
8. **目で見る**：全ページを画像にして，pptx スキルの Visual QA の項目（はみ出し・重なり・割れた語など）に加えて，一字だけの行，題と本文の対応，強調の数，群の色を一枚ずつ確かめる．直したら描き直し，指摘が 0 件になるまで繰り返す．
9. **離れて読む**：ポスターを横 600 ピクセルに縮めた画像で，題・要点の帯・結論が読めること．
10. **色**：dataviz の検証で，隣り合う群の差が通常の色覚で ΔE 15 以上，色覚の模擬で 8 以上．本文と背景のコントラストが 4.5:1 以上（design:accessibility-review）．ポスターの部品に §4 の値のほかの色と §3 のほかの大きさ・書体が 0 件（design:design-system）．
11. **別の目で批評する**：design:design-critique の枠組みで，作った本人の結論を渡さず，画像だけを見せて批評を受ける．指摘は §4 の二つ（学会ポスターの普通の形，教授が見た版の見た目）に照らして採否を決める．直前の版と並べて，同じポスターと分かること．
