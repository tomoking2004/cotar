# 発表資料の原則

`presentations/` の全資料（ゼミのスライド・学会のポスター）に適用する．**決定はこの文書が唯一の在処であり，各 pptx はこれを実装する**——食い違ったら，どちらが正しいかをここで決めてから直す．学会が定めるもの（講演番号・ボードの寸法・発表形式．[abstract.md](abstract.md)）は学会の定めが優先する．何を主張するか・数値をどう出すかは [.claude/context-philosophy.md](../.claude/context-philosophy.md) の領分で，予稿の組版は [papers/principles.md](../papers/principles.md) の領分である．本原則は，それらを**聴き手の前に置く形**だけを扱う．

節は，資料を作るときにぶつかる問いの順に並べてある——何を言うか（§1），どの順で言うか（§2），どう書くか（§3），どう見せるか（§4），ファイルをどう扱うか（§5），そして確定前に何を確かめるか（§6）．

## 1. 中身——研究文書と同じことを，同じ強さで言う

**資料は研究文書の要約であって，新しい主張の置き場ではない．** 研究文書（[.claude/context.md](../.claude/context.md)）に無いことは書かない．研究文書が「向きを決められない」と書いたものを「高めた」と書かない．

- **値は `analyses/` から取り，表示の桁で丸めたものだけを載せる．** 研究文書の文から値を写さない（研究文書もまた要約である）．差は丸める前の値から計算する．載せた値はすべて，§6 の照合で出どころを言えること．
- **主張の強さを，研究文書の語で保つ．** 区間が 0 を含む差は「向きを決められない」，相対感度の低下は「頼る度合いが下がる」（「使っていない」ではない），帰属できない効果は「〜には帰せない」．字数を詰めるために強さを変えない——短くするなら，主張を減らす．
- **測った量は，測った名で呼ぶ．** 「安定性」「頑健性」のような概念名は，それを何で代表させたか（比・距離）と組で出す．距離そのものと比が逆を向くなら，比だけを載せない．
- **同じものを二通りに呼ばない．** 研究文書の語（整合・タスク署名・読み取り精度・相対感度・baseline／proposal／ablation）を資料の全体で通す．言い換え（「揃えた」「重み」）は，同じものが別のものに見える．
- **除いて何も失われない要素は載せない．** 引用していない文献，誰も読まない注記，同じ値の二度目の掲載，作業の経緯（「〜を直した」「初案から変えた」）は置かない．発表者のメモは話す原稿であり，作業の記録ではない．
- **借りたものには出典を付ける．** 他者の手法・指標・画像は，その場で番号か名前で引く．参考文献は引いたものだけを，**初めて引いた順**に並べる．書式は [papers/principles.md §5](../papers/principles.md#5-相互参照と文献) に揃える（国際会議は「in Proc. {会議名}」，誌名と会議名は斜体，*et al.* は斜体）．

## 2. 構成——一枚に一つの主張を，論理の順に

**各スライド・各区画が言うことを一文で言えること．** 言えないなら，割るか削る．

- **題は内容を名指す．** 題と本文が別のことを言っていないか，本文の半分しか覆っていない題になっていないかを確かめる．同じ種類の題は同じ形にする（「〜の比（第16層）」のように，修飾の付け方まで揃える）．
- **流れは，問い→方法→結果→読み→次の手，の順に置く．** 結果の前に，その結果の読み方（判定の表・区間の読み方）を置く．読みは結果のすぐ後に置き，結論は最後にまとめて言い直す．
- **ゼミのスライドは，前回の結論から入る．** 前回からの差分（今回したこと）を最初に示し，「今後の目標」は研究文書の計画（§8）の順序と一致させる．
- **ポスターは，離れて立った聴き手が上から読む．** 題と要点の帯だけで主張が伝わること．本文は段組を左から右へ，各段を上から下へ読む順にし，章番号でその順を示す．講演番号は題の近くに大きく置く．
- **予稿と同じ章立てを保ち，予稿以後に足した結果はそうと分かるように置く．** 予稿の数値と食い違う値を載せない．

## 3. 文字——大きく，少なく，一つの規則で

**読ませるのではなく，見て分かる量に絞る．** 文で説明したくなったら，話す側（メモ）へ回す．

- **大きさの下限．** スライドは本文 24pt・二段目 20pt・表と図と注記 14pt 以上．A0 のポスターは本文 27pt・図表の文字 20pt・参考文献と画像の出典 15pt 以上．同じ役目の文字は同じ大きさにする．
- **句読点は「，．」．** 箇条の末尾には句点を打たない．文として完結した段落にだけ打つ．
- **全角と半角．** 英数字は半角．和文の中の括弧は全角（），英文と数式の中は半角 ()．全角の英数字・記号（＝＋＜＞％）と半角カナは使わない．負号と引き算は −（U+2212），範囲は –（U+2013，「18–28%」），波ダッシュ「〜」は使わない．値や語句を並べる区切りは「／」，欧文の語の中（yes/no）は半角の「/」．
- **空白．** ラテン文字の語（baseline，GQA，Wani）と和文の間には半角スペースを1つ入れる．数字と和文の間，数字と単位の間，単位と和文の間（「第16層」「1.7pt以内」「12,578問」），全角の括弧・句読点・記号の隣には入れない．数式の二項演算子（=，×，÷，−）は両側に1つずつ入れる．
- **数値の書き方．** 比率は「%」，差は「pt」，区間は「[下限, 上限]」．4桁以上は3桁ごとに「,」．同じ量は全資料で同じ桁に丸める．
- **強調は，一枚に一つの結論にだけ使う．** 赤字はその枚（区画）の結論か，聴き手の目を最初に向けたい一点だけに付ける．群の色（§4）と重なる赤は，その群の値にしか付けない．太字は見出しと，ポスターで要点を示す語に限り，段落全体を太字にしない．
- **誤字を残さない．** 用語の揺れ（§1）・送り仮名・変換の誤り・表と本文の数値の不一致を，§6 の走査で確かめる．

## 4. 図と面——色・形・余白を，一つの規則で

**同じものは同じ形，違うものは違う形にする．** 装飾のための色や線は足さない．

- **群の色は全資料で固定する．** baseline は灰色（`A6A6A6`），proposal は赤（スライドは `FF0000`，ポスターは `C00000`），ablation は水色（`9DC3E6`）．表・グラフ・本文のどこで群を色分けしても，この対応を変えない．色だけで区別させず，凡例か群名を添える．
- **ポスターの基調色は緑 `70AD47`**（前期のポスターを踏襲）．章の帯・表の見出し・要点の枠にだけ使い，淡い緑（`E2F0D9`・`EBF1E9`）を地に使う．スライドは白地に黒の文字で，色は群の色と強調の赤だけにする．
- **グラフは，軸の量と単位を書く．** 凡例・軸・目盛の文字は全グラフで同じ書体・大きさ・色にする．値を読ませたい棒には値を添える．
- **表は，見出しの行で量と単位を言う．** 同じ資料の表は同じ表の様式（表スタイル）を使う．
- **余白で区切る．** 区画どうしの間隔は揃え，詰まった所と空いた所を作らない．文字が枠からはみ出す，枠どうしが重なる，一字だけの行が出る，語や数値と単位が行を割れる——を残さない．スライドの端から 0.5 インチ，ポスターの端から 2cm は文字を置かない．
- **一般の体裁から外れない．** ゼミのスライドは研究室の雛形（表紙・題の位置・書体・箇条の形）に従う．学会のポスターは，題・著者・所属を上に，本文を段組に，参考文献を末尾に置く．ボード（横 180cm × 縦 90cm）に収まる判（A0 横）にする．

## 5. ファイル——部品を保ち，開き直して確かめる

**既存のファイルは，書式ごと作り直さない．** 直すのは部品（XML）の水準で，文字を差し替えるのを基本とする．

- **python-pptx で書き直さない．** 読む・確かめるのには使ってよい．python-pptx が書くと壊れる既知の点——チャートの一つの文字指定に `a:latin` が二つ入る，`c:axId`・`c:crossAx` が負になる——を持ち込まない．
- **作業の経緯をファイルに残さない．** 発表者のメモとコメントにも書かない．文書のプロパティの作成者は本人にする．
- **文字の言語は日本語（`ja-JP`）にし，テーマの東アジアの書体に日本語の書体を当てる．** スライドは研究室の雛形の書体（游明朝・游ゴシック），ポスターは游ゴシックである．
- **参照されない部品を残さない．** 消したスライド・画像・チャートの部品と関係（rels）は一緒に消す．
- **書いたら，保存したファイルを開き直して確かめる**（§6）．
- **PDF を本人の環境の外（LibreOffice など）で書き出すときは，日本語の文字に日本語の書体が当たるようにする．** 游明朝・游ゴシックが無い環境では，日本語版の代替（IPAex 明朝・IPAex ゴシックなど）を書体の別名として当てる．PDF は，直した回のうちに最終のファイルから書き出し直す．
- **更新したら，そのたびにファイルを本人に送る**（[CLAUDE.md](../CLAUDE.md)）．

## 6. 確定前の走査

**綺麗に見えることは根拠にならない．以下がすべて期待値を返してから確定する．**

1. **値の照合**：資料に載る数値をすべて抜き出し，`analyses/*.json`（問ごとの値は `analyses/probe-drift.pt`）から計算し直した値と一致させる．一致しない値・出どころを言えない値が 0 件．
2. **部品の検証**：ISO/IEC 29500 のスキーマ（Markup Compatibility を処理してから）と Open XML SDK（DocumentFormat.OpenXml 3.1.0）の検証がともに 0 件．python-pptx で開き直せる．参照されない部品が 0 件．
3. **書体**：書き出した PDF に埋め込まれた書体に，名前に SC・TC を含むもの（中国語の書体）が 0 件．
4. **文字の走査**（0 件）：「、。」，全角英数字・半角カナ，全角の ＝＋＜＞％，「〜」，ハイフンの負号（数字の前の `-`），ラテン文字の語と和文のあいだの空白の欠け．
5. **目で見る**：全ページを画像にして，はみ出し・重なり・詰まり・一字だけの行・割れた語，題と本文の対応，強調の数，群の色を一枚ずつ確かめる．直したら描き直し，指摘が 0 件になるまで繰り返す．
