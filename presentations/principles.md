# 発表資料の原則

`presentations/` の全資料（ゼミのスライド・学会のポスター）に適用する．**決定はこの文書が唯一の在処であり，各 pptx はこれを実装する**——食い違ったら，どちらが正しいかをここで決めてから直す．学会が定めるもの（講演番号・ボードの寸法・発表形式．[abstract.md](abstract.md)）は学会の定めが優先する．何を主張するか・数値をどう出すかは [.claude/context-philosophy.md](../.claude/context-philosophy.md) の領分で，予稿の組版は [papers/principles.md](../papers/principles.md) の領分である．本原則は，それらを**聴き手の前に置く形**だけを扱う．

節は，資料を作るときにぶつかる問いの順に並べてある——何を言うか（§1），どの順で言うか（§2），どう書くか（§3），どう見せるか（§4），ファイルをどう扱うか（§5），そして確定前に何を確かめるか（§6）．規則に添えた「本人の指摘」「本人の指示」「教授の指摘」「別の目の批評」「別の目の照合」（作った文脈を持たない別の実行の読み．批評は §6 の11 の画像の批評，照合は原典や研究文書との突き合わせ）と日付は，その規則の出どころである．

**見せ方の方法はスキルが持ち，この資料での決定は本書が持つ．** 色の検証や部品の編集の方法はスキルの領分で，本書には写さない．本書に書くのは，決めた値と，スキルの既定と違う決定だけである．スキルの既定はスライドや Web を想定したものが多く，学会のポスターにそのまま当てない．食い違ったら，学会の定め，教授の指摘，本書，スキルの既定の順に優先する．

## 1. 中身——研究文書と同じことを，同じ強さで言う

**資料は研究文書の要約であって，新しい主張の置き場ではない．** 研究文書（[.claude/context.md](../.claude/context.md)）に無いことは書かない．研究文書が「向きを決められない」と書いたものを「高めた」と書かない．

- **値は `analyses/` から取り，表示の桁で丸めたものだけを載せる．** 研究文書の文から値を写さない（研究文書もまた要約である）．差は丸める前の値から計算する．載せた値はすべて，§6 の照合で出どころを言えること．
- **主張の強さを，研究文書の語で保つ．** 区間が 0 を含む差は「向きを決められない」，相対感度の低下は「依存する度合いが下がる」（「使っていない」ではない．研究文書の「頼る」は口語的なので資料では使わない．教授の指摘，2026-11-09），帰属できない効果は「…には帰せない」．字数を詰めるために強さを変えない——短くするなら，主張を減らす．
- **区間が 0 を含み，両端とも ±2pt 以内の差は「ほとんど変わらない」と書く．** 正解率（[−1.81, +1.70]pt）や答えが変わった割合（[−0.60, +0.32]pt）で聴き手に要るのは，ほとんど変わらないことである．「群の差の向きは決められず」は初見で意味が伝わらない（教授の指摘，2026-11-09）．研究文書も正解率を「ほとんど動かない」と書く．結果の見出しでは「3群でほとんど同じ」とする．それより広い区間が 0 を含むときは向きを決めず，ポスターでは「差ははっきりしない」（一行に収まらなければ「差が不明瞭」）と書く．
- **同じ基準を全章に当てる．** ある章で「向きを決められない」と書く条件（区間が 0 を含む）の差を，別の章で「低下」とだけ書かない．範囲で言う値の端が区間で 0 を含むなら，そう添える．限定のある文（「幾何的な加工では」）から限定を落とさず，整合の前から成り立っていること（「読み取れる」）を，整合の効果のように書かない．
- **指標ごとに，測った問の範囲を書く．** 指標によって問の数や抽出が違うなら，評価の問数だけを書いて全指標に掛かるように見せない．ポスターでは 3.1 の評価の行に「3.2 の相対感度は64問」と添え（相対感度は 3.2 で定義するので，行き先を名指す），読み取り精度は方法の行で「10問以上ある署名で」と言う．学習の問数と回数は，何をした数かを書く（「GQA[2] の942,116問から16署名 × 2問を引き，モデルの重みを1回更新」「毎回引き直して，これを29,441回繰り返す」．「942,116問から抽出」は抜き出した数が別にあるように，「16署名 × 2問ずつ引き」は一度引いた32問で学習したように読める．「…引いて更新し，これを29,441回」は回数に動詞が無く，「29441回何するんですか？」と問われた（教授の指摘，2026-11-13）．研究文書 §4.1）．判定の行は，判定の基準まで書く（「…が 0 を含まなければ差あり」）．
- **測った量は，測った名で呼ぶ．** 「安定性」「頑健性」のような概念名は，それを何で代表させたか（比・距離）と組で出す．ポスターでは，本研究の測った量の結果と結論に概念名を使わず，測った向きで言う（「加工で 𝒉 が動きにくくなった」．「安定性　ってなんですか？」教授の指摘，2026-11-09）．比を見せて距離を載せないなら，比が示したことだけを結論にし，分母の変化をその前に添える——群ごとに分母が違う比の低下は，動きにくくなったことを意味しない．
- **同じものを二通りに呼ばない．** 同じものは資料の中で一つの名で呼ぶ．名は研究文書の語（整合・タスク署名・読み取り精度・相対感度・baseline／proposal／ablation）を基本とし，ポスターで別の語にするもの（「タスク署名」を出さない，解き方を「手順」と呼ぶ）は §2 の各項に従う．言い換え（「揃えた」「重み」）は，同じものが別のものに見える．
- **スライドだけで全部が伝わるようにする．** 発表者のメモは，本人も聴き手も読まない．だからメモは空にしておく——メモにしか無い情報は，伝わらない情報である．定義，理由，出典（「Wani らに倣う計算」のような），原典との違い，測る前に決めた読み方は，メモではなくスライドに置く．枚数は増やしてよい．本筋の理解に要らない細部（原典との設定の細かな違いのような）は，本編から外して補足資料（参考文献の後）に回す．
- **本編は，文ではなく短い語句で書く．** 一枚の主張を，短い語句の箇条書き・図・表で一目で分かる形にする．箇条はできるかぎり体言止めにする（「内部表現は変化」「正解率：ほぼ不変」）．対比は「A ／ B」や表にし，文を連ねない（矢印の使いどころは §3 の矢印の項）．ポスターの結論は，専門外の人が読んで分かる一文にする．≠ のような記号で主張を言わない——「読み取れる ≠ 使われる」は，何を言いたいのか聴き手に伝わらなかった（教授の指摘，2026-11-06）．問いだけは問いの形で残す（§2）．ポスターでは手法の説明と目的の行も例外にせず，「〜を追加」「〜の確認」のように語句で閉じ，理由は次の行の頭の「→」で受ける（§3 の矢印の項）．文のまま残すのは，問いと，キーアイデアと結論の一文だけである．文字を小さくして詰め込まない（§3 の大きさを守る）．
- **聴き手の判断に要らない語と細部は載せない．** 専門語（「双三次」のような）や原典の細部（「最も小さいモデルで」のような）は，聴き手が結論を判断するのに要らなければ削る．要るなら，その場で平易な語で言う．縮めすぎて理由が読めなくなった一文（「予測で文を変えると，群ごとに画像が変わる」）は，縮める前の因果に戻す．
- **除いて何も失われない要素は載せない．** 引用していない文献，誰も読まない注記，同じ値の二度目の掲載，作業の経緯（「〜を直した」「初案から変えた」）は置かない．
- **測った量は，何と何を比べた量かと，値の意味を，一文ずつ書く．** どの層・どの位置のどのベクトルどうしの距離か，比なら分子と分母が何で，値が大きい／小さいと何を意味するか（「比：加工による動きが，別の画像に替えたときの動きの何%か」）．別の作り方で測り直したなら，作り方そのものを名前にする（「平均を中央値に替える」）．似た量は，割り算の形で書き分ける（動きの比：「動き ÷ 画像だけ替えたときの動き」，答えが変わった割合：「答えが変わった組 ÷ 全組（組：問1つと加工1つ）」）——「比」と「割合」を名だけで並べると，どう違うのか曖昧に見える（教授の指摘，2026-11-09）．割り算の分母は，コードが数えるものに合わせる——答えが変わった割合は問と加工の組で数える（Wani らの instance flip rate．`cotar/analysis/drift.py`）ので，「答えが変わった問 ÷ 全問」と書くと誤りになる．
- **群は群名で指す．** 「群」という語そのものを，実験設定で定義してから使う（「比べる3群：学習の仕方だけが違う3つのモデル」．定義の無いまま「群ごとに」と書いて「群　って何？」と問われた．教授の指摘，2026-11-09）．各群は，何をして学習したかを，何をしたかが目に見える語で行ごとに書く（baseline「整合損失なし：通常の損失 ℒLM だけで学習」，proposal「整合損失あり：署名が同じ質問の 𝒉 を近づける」，ablation「整合損失あり：署名を質問間で無作為に入れ替え，手順と無関係な相手を近づける」）．ablation を「署名を並べ替え（意味だけを除く）」と書くと，何が除かれたのか伝わらない（本人の指摘，2026-11-08）．「並べ替える」は署名の中の操作の順を並べ替えるとも読めるので，質問のあいだで無作為に入れ替えると書く（別の目の批評，2026-11-12）．「質問どうしで」でなく「質問間で」とするのは，24pt で表の一行に収めるためである（2026-11-13）．「整合の有無と，整合に使う署名だけを変えて学習」のような要約は，「整合の有無って何ですか？曖昧」「よくわからない」と問われた（教授の指摘，2026-11-11）．「整合した群」のように二つの群に当てはまる言い方をしない（ablation も整合損失を掛ける）．一つなら proposal，二つなら「proposal と ablation」と書く．
- **分類と族は，どれがそれかを見せる．** 「幾何的な加工（5族）」のように分類に触れるなら，加工の表に区分の列を設けて示す．同じ操作の変種は，名前でも同じ族と分かるようにする（「指示文の重ね書き」「無作為な文字列の重ね書き」「文字なしの重ね書き」）．
- **比喩と内輪の語を使わない．** 「物差し」「探索的」のような語は，何をしたか・なぜそう読むかに置き換える（「族ごとの区間は8つ作るので，偶然0を外れうる」）．
- **借りたものには出典を付ける．** 他者の手法・指標・画像は，その場で番号か名前で引く．借りた尺度は，方法の行で借りたと書く（「Wani ら[1]に倣う尺度」）．作り方を変えた所があれば，そこを名指す——動きの比の分母は，Wani らの無関係な画像の対ではなく，同じ質問で画像だけを替えたときの距離なので，「Wani ら[1]の尺度」と言い切らず「倣う」とし，分母を画像だけ替えたときの距離と書く（別の目の照合，2026-11-12．研究文書 §A.6）——書かないと，勝手に考えた尺度と思われる（教授の指摘，2026-11-09）．カードでは「動き：加工の前後の 𝒉 の距離」「比：動き ÷ 画像だけ替えたときの動き」と書く．割り算の両辺は量の名で書く——「加工の前後 ÷ 画像だけ替えたとき」は量が落ち，「その何%か」は指す先が曖昧になる（別の目の批評，2026-11-13）．参考文献は引いたものだけを，**初めて引いた順**に並べる．書式は [papers/principles.md §5](../papers/principles.md#5-相互参照と文献) に揃える（国際会議は「in Proc. {会議名}」，誌名と会議名は斜体，*et al.* は斜体）．

## 2. 構成——一枚に一つの主張を，論理の順に

**各スライド・各区画が言うことを一文で言えること．** 言えないなら，割るか削る．

- **題は内容を名指す．** 題と本文が別のことを言っていないか，本文の半分しか覆っていない題になっていないかを確かめる．同じ種類の題は同じ形にする（「〜の比（第16層）」のように，修飾の付け方まで揃える）．
- **前に出ていないものに触れない．** 今回の資料で新しく出す語・記号・指標は，使うより前のスライドで定義する．各スライドの主張は，それより前のスライドだけから導けること．
- **聴き手が既に知っている語は，定義し直さない．** 分野で通じる語（VLM・対照学習）と，研究で使い続けている語（署名・整合・baseline／proposal／ablation）は，そのまま使う——教授が知っているものを一から定義すると，枚数と文字が増えるだけである．学会のポスターは専門外の人も読むので，研究で使い続けている語は使う前に定義する．
- **流れは，問い→方法→結果→読み→次の手，の順に置く．** 読みは結果のすぐ後に置き，結論は最後にまとめて言い直す（ポスターはまとめの章を置かず，要点の帯が結論を言う．この節の「ポスターにまとめの章を置かない」の項）．結果の読み方（判定の表・区間の読み方）を独立したスライドにするのは，聴き手が初めて見る指標を出す発表だけで，進捗報告には置かない．
- **結果は，まず一枚の一覧で見せる．** 測った量（層・比と距離・回答）と群の比較を一つの表に並べ，区間が0を含まないものを太字にする．族ごと・作り方ごとの詳細は，一覧の後に，一覧に無いことだけを載せる．本筋で見せる群の比較は，問いに答えるもの（proposal − baseline と proposal − ablation）に絞る．
- **ゼミのスライドは，前回の結論から入る．** 前回からの差分（今回したこと）を最初に示し，「今後の目標」は研究文書の計画（§8）の順序と一致させる．
- **進捗報告は，聴き手の判断に要るところまでで止める．** 見積もりの式，乱数種ごとの値，本数を決めた理由のような裏付けは本編から外す（§1）．読み方の分岐の表は，結果のある回にも載せず，当てはまる読みだけを結果の後に言う．枚数は内容に見合う分にする．ポスターの作業の話と，研究文書の更新のような記録の作業は載せない——進捗報告は簡潔でよい（本人の指示，2026-11-06）．ただし，研究の進捗が無い回は，前回の振り返りと，その間にしたことを一行で言うだけの簡単な資料にする（「指摘を受けながら，ポスターを改善」．送った日付・発表の日時・実験が無いことは書かない）．ポスターを作っている時期は，最後のスライドにポスターを全面に貼り，教授がゼミでそれを見て指摘できるようにする（本人の指示，2026-11-12）．
- **ポスターは，離れて立った聴き手が上から読む．** 題と要点の帯だけで主張が伝わること．本文は章番号の順に読めるように置き（段組でも，行の組でもよい），章番号でその順を示す．講演番号は題の近くに大きく置く．題は和文だけにし，英題は載せない．
- **ポスターの要点の帯には，研究の問いとわかったことを，専門外の人に分かる語で置く．** 結果の数値だけを先に出すと，何の研究で何が要点かが分からず，その良し悪しを判断できない．アイデアは帯に置かない——一言に縮めると言い過ぎになり（「内部表現に明示的に持たせる」），目的と問いを欠いたアイデアでは，聴き手が置いて行かれる（教授の指摘，2026-11-09）．わかったことは，問いと並べて初めて意味が分かる．帯は聴き手が最初に読むので，それまでに説明していない語（「解き方」）を出さず，何のことか分かる語（「答えに至る手順」）と例で書く．研究文書の「解き方」は，ポスターの全体で「手順」と呼ぶ．手順の例は，質問文と並べ，質問に即した語で書く（「質問：What's the girl holding?」「手順：女の子を見つける → 持っている物へたどる → それが何かを答える」．「名前を答える」は質問の語ではない．教授の指摘，2026-11-11）．例の行の見出しは「手順：」とし，「答えに至る手順：」と繰り返さない——すぐ上の問いが「答えに至る手順」と言っている（本人の指摘，2026-11-12．教授の案は「答えに至る手順：…　みたいな感じ」だった）．

- **図の例は，実際の写真と質問で，図の中で辻褄を合わせる．** 模式図より実際の写真のほうが学会発表らしい．VQA の図なので入力には質問文を置き，出力には具体的な答えを置く．例は評価データから選び，言うことを実測で確かめる（背景の図なら，モデルがどの乱数種でも正解し，加工で答えが変わらない問）．一つの問の量は乱数種で大きく揺れるので，確かめるときは全乱数種を見る．ただし，背景の図（先行研究の説明）には本研究で測った値を載せない——先行研究の結果と読まれる（「内部表現の動きは別の画像の42%」を Wani らの結果かと問われた．本人の指摘，2026-11-08）．確かめた値は研究文書と報告に置き，図は先行研究の方法の模式とする．質問を添えた画像にはその質問の答えが写っていること（ドレスの写っていない写真に “Who is wearing the dress?” を添えない）．矢印は実際の流れどおりに引く（内部表現は VLM の内部から取り出すもので，答えに直結するものでも，答えから出るものでもない）．同じ例を，背景の図・手順の例・手法の図・加工の例で通す．
- **背景の先行研究は，結果だけでなく，目的と方法を書き，簡単な図で示す．** 手法の前提になる例（「見つける・たどる・答える」のような手順）を説明なしに先に出さない．手法の語は背景に持ち込まない（署名は実験設定で定義する．§2）．先行研究の図は，原典が測った位置で描く——Wani らは内部表現を最終層の後から取る（原典 §3.3 “extract hidden states from the final transformer layer”）．2章の 𝒉 と同じ中間の層から取る図にすると，Wani らも中間層を測ったと読まれる（別の目の照合，2026-11-12）．先行研究の結果から何が言えるかは，問いにつながる形で書く（「答えだけでは，内部の様子は不明」では何を言いたいのか伝わらない）．仮説は問いの形で終え，それまでに出ていない観点を持ち込まない．
- **先行研究から問いへは，段を踏んで導く．** Wani らの結果（加工で答えは同じでも内部表現は変わる）→ 人間についての問い → functional program が何かを説明する → 例 → 問い．**この段の文言は教授の5回目の指摘（2026-11-13）のとおりにする**：人間の文は「人間は画像加工の有無にかかわらず同じ手順を踏んで答えを導くのではないか？」，次の行は手順そのもの（「女の子を見つける → 持っている物へたどる → それが何かを答える」．「上の質問なら，どちらの画像でも」は「カット。女の子を見つける　からスタートでOK」），program の行は「人間が行う視覚的推論を計算可能な操作の列で表現したもの：functional program[2]」（行頭の「→」は「いらない」），問いは「答えに至る手順を VLM の内部表現が獲得できれば，正解率は上がるか？」．行頭の → は，人間の文からも外して揃える．1章の用語の箇条の「答えに至る手順：答えを導くために順に踏む推論の段階」は「カット」と言われたので置かない——何が手順かは，帯の例と，人間の文の次の行と，program の例が見せる．人間の文が「画像加工の有無にかかわらず」と，何と何が同じかを言うのは，「同じ手順を踏んで答えを導く」だけでは「何と何が同じなんですか？」と問われたからである（教授の指摘，2026-11-11）．例は質問と答えであることを明記する（「質問：What's the girl holding?　答え：racket」．「what's the girl holding? -> racket が何なのかよくわからない」同）．先行研究が示していないこと（11/8 の版の「人間が画像を見て答えに至るまでの手順の特徴を，内部表現は獲得できていない可能性」）を，その結果からの帰結のように書かない——Wani らが示したのは，答えが同じでも画像の変化が内部表現を動かすことまでである（教授の指摘，2026-11-09）．program の行の「人間が行う」は，教授が二度求めた（2026-11-09 のコメント，2026-11-13 の差し替えの指示）著者の読みである．GQA の論文は “a functional program which lists the series of reasoning steps needed to be performed to arrive at the answer”（§3）と書き，人間の手順とは書いていない（[references/gqa.md](../references/gqa.md) の「ポスターとの対応」）．だから人間についての前の行を問いの形に保ち，program の行に原典の主張と読ませる語（「GQA によれば」のような）を足さない．本人は 2026-11-09 に原典の定義どおりに書くと判断したが，教授の差し替えの指示（2026-11-13）を優先する．出どころは引用番号だけにし，データセット名の括弧を足さない（「functional program[2]」．「データセット GQA…」はカット，教授の指摘，2026-11-11）．
- **結果は，目的 → 方法 → 結果 → 考察の順に書く．** わかったことを先に書かない．各グラフの前に，何のためにどう評価したかを書く——評価尺度は，採用した目的を言わないと聴き手に意味が伝わらない．各グラフの「結果」の見出しは，数値の大小や順位（「proposal が最小」「8・32本で proposal だけ低下」）ではなく，そこから分かること（「答えの 𝒉 への依存が低下」「3群でほとんど同じ」）にし，どの群が動いたかだけを灰の小さな行に置く（「で、何がわかるの？と思われる」教授の指摘，2026-11-09）．**ポスターでは差の値と区間を書かない**（区間の項）——どれくらい差があるかはグラフで見える（「細かい結果の数値（何pt上昇した等のところ）、削ってよくないですか」教授の指摘，2026-11-11）．聴き手は細かい数値の大小に興味がないので，区画の末尾に，結果から示唆されることを大きな文字で枠に置く．枠はどの節も同じ形にする——「考察」に続けて結論の根拠を一行で書き，大きな太字（スライドは赤，ポスターは緑．§3）で読みを置く．3.2 と 3.3 の結論は，同じ 36pt の2行にそろえ，枠の中の「考察」の行の高さを揃える——片方だけ 44pt の1行にすると，役目の同じ字の大きさと行の位置がずれる（別の目の批評，2026-11-12）．その大きな字に結果の言い直しを置かない（3.3 は「𝒉 の動きの比は小さくなったが，𝒉 が動きにくくなったとまでは言えない」までが読みである．前半を「加工による 𝒉 の動きは小さくなった」と書くと，後半と矛盾に読める——比の話であることを，結果の見出し（「比で見た 𝒉 の動きが縮小」）でも名指す．別の目の批評，2026-11-09）．根拠の行は，測った量と倍率で言う（何との倍率かを名指す．「proposal は 𝒉 の動き自体が baseline より大きい．加工で約3倍，別の画像で約5倍」）．「𝒉 の広がり自体が変化」のような語は，何が広がったのかが伝わらない（本人の指摘，2026-11-08）．研究文書が確かめていない因果（「対照学習が埋め込み空間を押し広げた」）は書かない．
- **評価尺度と比べる水準は，何を確かめるためか，入力が何かを書く．** 比べる水準を置くなら，見出し語は「対照」でなく「比較」とし（「対照」は専門外に通じない．教授の指摘，2026-11-09），その中身（「右端は，質問文の語だけで見分けた割合」）と，上回ったら何が言えるか（「→ 𝒉 が上回れば，語では説明できない」）を書く——書かないと，なぜその棒があるのか読み手に分からない（本人の指摘，2026-11-08）．「質問文を読むだけで当たる水準」では何を言いたいのか分からなかった（教授の指摘，2026-11-11）．「当てる」と書かず「見分ける」と書き，見分ける対象を前に置いた語で言う（「𝒉 だけから線形分類で署名を見分ける」．「署名　当てる　って何ですか？当てるとは」同）．正解率は，何と何を照合したかを書く（「生成した答えが正解と一致した問の割合／照合：GQA 公式の評価スクリプト」．「評価スクリプトをどう使ったんですか？これが ground truth ってこと？」同）．正解が GQA の正答であることは「GQA 公式の」で読めるので，「正解：GQA に付属する正答」の行は置かない（自明な情報は不要，本人の指摘，2026-11-12）．「正解率」は答えの正解率だけに使い，読み取り精度の分類器には「正しく見分けた割合」と書く——隣り合う図で同じ語が別の量を指すと，取り違える（別の目の批評，2026-11-12）．横軸の量（方向の本数のような）は，それが何の数かを名指し，方向そのものを平易な語で定義する（「方向：racket などの答えの語を選ぶ，出力層の主な向き．横軸は取った向きの本数」．「答えの語にあたる重み」「横軸の本数　って何？」同）．
- **ポスターは区間の値を載せず，判定の基準を実験設定で一度だけ言う．** 「判定：乱数種を対にした t 検定で求めた，群の差の95%信頼区間が 0 を含まなければ差あり」と書く（教授の指摘，2026-11-11）．一部の結果にだけ載せることもしない——載せた所と載せない所があると不揃いに見える（本人の指摘，2026-11-08）．区間で決まる強さは語で残す．区間が 0 を含む条件があるなら，灰の行にそう添える（「proposal だけ低下．128本は差が不明瞭」．24pt の一行に「差がはっきりしない」が収まらないので，§1 の「差が不明瞭」を使う）．見出しは分かることで書き（上），条件を見出しに並べない．ゼミのスライドは，これまでどおり値と区間を載せる．
- **加工の例に並べる加工でない画像は，名で分ける．** 3.3 の写真の6枚目は加工ではなく，動きの比で画像だけ替えたときの画像なので，写真の名を「別の画像」とし（加工の名と同じ形にしない），何のための画像かは動きの比の方法の行（「比：動き ÷ 画像だけ替えたときの動き」）と写真の出典（「「別の画像」は説明のための例」）が言う．加工の例の見出しの下に「「別の画像」は加工でなく，分母に使う」と添えた版は，「いきなり「分母」と言っても何のことか分からない」と言われた（本人の指摘，2026-11-12）——まだ出ていない語を注で使わない（§3 の注の語の項）．
- **主筋の外の検証は，主筋との対比が分かるようにする．** 節の題は，その節が答える問いの形で中身を名指し，頭に「解析①」「解析②」と節の種類を付ける（「3.2 解析①：手順の情報は内部表現に表れ，答えに使われるか」「3.3 解析②：画像を加工しても，内部表現は動きにくくなるか」．「追加の検証」としない．頭の語は教授の指摘，2026-11-11）．**題の下に，その解析が何のためか（何がわかるか）を「ねらい」の行で素人の語で言う**——3.3 は「ねらい：加工しても手順は同じ．加工で 𝒉 が動きにくければ，𝒉 は見た目より手順を表すとわかる」と，予想でなく，測ると何がわかるかの形で言う（「内部表現　h が動きにくくなることを測ると何がわかるんですか？素人にもわかるように明確に説明する」教授の指摘，2026-11-13．1章の人間の文と同じ見方で，動きにくさが，𝒉 が手順を表すかを示す）．3.2 は「ねらい：1章の問いに答える．手順の情報を持たせた proposal の正解率が上がるかを見る」とし，二つの節の頭の行数を揃える．何を入力にしたかの違いは，ねらいの次の入力の行で言う（教授の指摘「何を入力にして，何にしたという対比が説明されていた方がよい」，2026-11-06）．題そのものを「元の画像を入力」「加工した画像を入力」の対比にしない——画像の加工は実験の一つであって，節を分ける軸ではない（本人の指摘，2026-11-08）．指標ごとに目的を添える．考察は結果の言い直しではなく，なぜそうなったと考えるかを書いたうえで結論を置く．
- **ポスターにまとめの章を置かない．** 3章で強調したことを，もう一度述べるだけになる（「ここ全部カットしてもいいような気がしてきた」教授の指摘，2026-11-11）．結論は，要点の帯のわかったことと，3.2・3.3 の考察の枠が言う．空いた紙面は，ほかの説明に回す．研究の範囲の注（「1モデル・1データセットでの結果」）は，実験設定の学習と評価の欄に置く．今後の展望と研究の意義も載せない（聞かれたら答える．教授の指摘，2026-10-29）．
- **予稿の流れ（はじめに→手法→実験）を保つ．** ポスターは実験の章で終える（上の項）．実験設定と結果は，一つの「実験」の章にまとめる．予稿の数値と食い違う値を載せない．予稿以後に足した結果に「予稿以後の測定」と書かない——聴き手の判断に要らない（教授の指摘，2026-11-09）．
- **実験設定では，何を同じ質問・違う質問とみなしたかと，比べる群の意味を書く．** 表は，何の表かを言う見出しの行（「比べる3群：学習の仕方だけが違う3つのモデル」）と，読み方の行（「proposal が両方と違えば，その違いは署名の意味による効果」．「手順による効果」とは書かない——ablation が示すのは署名に意味が要ることまでで，署名が手順の正しい形式化であることは示さない（研究文書 §4.2，別の目の照合，2026-11-12））で挟む——説明の無い表は浮いて見える（教授の指摘，2026-11-09）．

## 3. 文字——大きく，少なく，一つの規則で

**読ませるのではなく，見て分かる量に絞る．** 一枚に収まらない説明は，メモへ回さず，スライドを割って一枚ずつ見せる．

- **大きさ．** スライドの本文は 24pt，二段目は 20pt に揃え（下限でもある），表と図と注記は 14pt 以上．A0 のポスターは 80／44／36／30／24／20pt の6種類だけを使う（題／講演番号・章の見出し・要点の帯／節の見出し・考察の結論／本文・図の部品の名・図の数式／図表の文字・指標の説明・注記／参考文献・写真の出典）．**概要図（§2）の部品の名と語（入力・層・出力層・トークン・答え・正方形の読み方・近づける／遠ざける）は本文と同じ 30pt にする**（「図中の文字もっと大きくする」教授の指摘，2026-11-13）．図の注（トークン・層への矢印・𝒉 の位置の説明）と整合損失の枠の質問文は 24pt にする．「全体的にフォントサイズが小さいのでできる限り大きくする。スペースを余らせない。」（教授の指摘，2026-11-13）により，72／44／36／28／22／16pt から，帯の一行に収まる 44pt と節の見出しの 36pt を除いて一段ずつ上げた．44pt を上げると帯の問いが2行に割れ，本文と図表の字をさらに上げると，3章のグラフの描画域（約2cm）が無くなる．題を除く隣どうしは 1.2–1.25倍で，読み分けられる差を保つ．間の大きさを足さず，どれかに寄せる——大きさの種類が増えると，一つ一つは正しくても，全体が雑然と見える．同じ役目の文字は同じ大きさにする．
- **ポスターの書体の太さと字間．** 本文は游ゴシック Medium にし（Regular は細く，離れると読みにくい），太字は合成でなく游ゴシックの Bold を当てる．游ゴシックの仮名は緩いので字間を詰める（題 1pt，要点の帯 0.6pt，本文と図表 0.4pt．PowerPoint には詰めの機能が無い）．
- **句読点は「，．」．** 箇条の末尾には句点を打たない．文として完結した段落にだけ打つ．
- **一つの語を，近くで別の意味に使わない．** 「通常の学習の目的は」を，Wani らの欄の見出し語「目的」の隣に置くと，同じ語が別の意味に並ぶ（「通常の学習が求めるのは」とする）．「出力」は，第32層の出力（ベクトル）と答えの両方に使わず，答えは「答え」と書く．「比で比べる」のような同じ語の近接も避ける（初見の読み手の批評，2026-11-12）．
- **同じ助詞を一つの句に重ねない．** 「答えの生成には十分には使われない」のように「には」が続くと，読みにくく美しくない（本人の指摘，2026-11-12）．意味を担うほうに残し，もう一方を外す——「十分には」は教授の指摘（「十分使われない　⇒　十分には使われない」2026-11-11）なので残し，「答えの生成に十分には使われていない」とする．書いたら，一つの句に「には」「では」が続いていないかを読み直す．
- **括弧はできる限り使わない．** 補足は括弧に入れず，語順を変えて本文に入れるか（「SmolVLM-500M-Instruct[3]：言語モデル部が全32層の軽量な VLM」），句点や読点で切って続けるか（「評価：学習に使わない12,578問，3.2 の相対感度は64問」），表なら列を立てる（3.1 の「上と同じ手順」「違う手順」）．括弧が多いと美しく見えない（本人の指摘，2026-11-12）．残すのは形の決まったものだけである——略語の導入（視覚言語モデル（VLM）．下の略語の項），量の単位（読み取り精度（%）），著者の所属，図の部品名に添えた一般の呼び名（言語モデル部（LLM）．§2 の概要図の項），語や図の名の引用（「別の画像」），文献の番号．
- **矢印は，順序と，前の行を受ける行頭にだけ使う．** 手順の順序（「女の子を見つける → 持っている物へたどる → それが何かを答える」）と，行の頭で前の行を受ける所（「→ 一方，…」「→ 上回れば，…」）に限る．一つの行の中で二つの文を → で継がない——「同じ手順の 𝒉 どうしが，違う手順より近いほど小さい → 下げると，𝒉 が手順ごとにまとまる」は冗長に見えた（本人の指摘，2026-11-12）．言いたいことを一つの語句で言い切る（「𝒉 を手順ごとにまとめる損失」）．
- **本文から図の番号を指すときは，図の番号と同じ見た目にする．** ポスターの図の番号は緑の丸に白抜きの数字なので，本文でも緑の白抜きの丸数字で指す（「中間の第16層から，下図❷の 𝒉 を取る」）．ただの文字の②と色の付いた図形の②では，同じものを指すと読めない（本人の指摘，2026-11-12）．図の番号でない丸数字（節の名の「解析①」．教授の指摘，2026-11-11）は白抜きにしない——同じ見た目にすると，図の番号と取り違える（§4 の「意味の違うものを同じ見た目にしない」）．
- **図の注で使う語は，図か，それより前の注で出しておく．** 「列から層への矢印：トークンの列が次の層へ進む流れ」の「列」は，それまでに一度も出ていない語だった（本人の指摘，2026-11-12）．図に書いた名（トークン）と，前の注で定義した語だけで書く（「層への矢印：全トークンが次の層へ進む．出力層へは末尾のトークンだけ」）．1章の「操作の列」と同じ語を，別の意味で持ち込まないためでもある．
- **全角と半角．** 英数字は半角．和文の中の括弧は全角（），英文と数式の中は半角 ()．全角の英数字・記号（＝＋＜＞％）と半角カナは使わない．負号と引き算は −（U+2212），範囲は –（U+2013，「18–28%」），波ダッシュ「〜」は使わない．値や語句を並べる区切りは「／」，欧文の語の中（yes/no）は半角の「/」．
- **空白．** ラテン文字の語（baseline，GQA，Wani）と和文の間には半角スペースを1つ入れる．数を一つの語として立てるとき（「区間が 0 を含む」）も同じにする．数字と和文の間，数字と単位の間，単位と和文の間（「第16層」「1.7pt以内」「12,578問」），全角の括弧・句読点・記号の隣には入れない．数式の二項演算子（=，×，÷，−）は両側に1つずつ入れる．
- **略語は，初出で「正式名（略語）」と書き，以降は略語だけにする．** 「視覚言語モデル（VLM）」の形で，予稿（manuscript.tex の「視覚言語モデル（VLM）」）と揃える——「VLM（視覚言語モデル）」は逆である（本人の指摘，2026-11-09）．初出は資料の上から数える．ポスターでは要点の帯が箇条の定義より先に読まれるので，帯では略語を使わず正式名で書き（題も正式名である），1章の箇条で略語を導入する．データセットとモデルの名（GQA・SmolVLM）は固有名で，略語として開かない．図の「言語モデル部（LLM）」は，予稿の部品名に一般の呼び名を添えたもので（本人の指摘，2026-11-08．§2 の概要図の項），この項の略語の形には当たらない．
- **数値の書き方．** 比率は「%」，差は「pt」，区間は「[下限, 上限]」．4桁以上は3桁ごとに「,」．同じ量は全資料で同じ桁に丸める．
- **強調は，一枚に一つの結論にだけ使う．** スライドでは強調の赤を，その枚の結論か，聴き手の目を最初に向けたい一点だけに付ける．赤は proposal の群の色と同じなので，群の値にはその群の値にしか付けない．ポスターは一つの色相で組むので（§4），結論は色ではなく大きさと太さで示す——要点の帯の二つの見出し（問いとわかったこと）と考察の枠の読みを，緑の大きな太字にする．帯の二つは同じ色にそろえる（片方だけ墨だと不揃いに見える．本人の指摘，2026-11-08）．太字は見出しと，ポスターで要点を示す語に限り，段落全体を太字にしない．
- **測った量の名は，それと分かる形にする．** ポスターでは，指標の名（読み取り精度・正解率・相対感度・動きの比・答えが変わった割合）を，緑の地に白抜きの太字の札にする（前期公開期末のポスターの表の見出しと同じ扱い）．札はほかに使わない——札を見れば「これを測った」と一目で分かる（本人の指摘，2026-11-08）．新しい色相（一度は紫にした）で分けない——色数が増えてまとまりを失う．構造の見出し（結果・加工の例）は緑の字のままにする．
- **字下げは一つの規則にする．** 見出し語（目的・方法・比較・方向・結果・考察・問い・例・加工の例，提案手法のキーアイデア・モデル・方法・整合損失）は緑の太字にし，その後はタブで本文の頭を揃え，続きの行もその頭に揃える（同じ「結果」が区画によって黒と緑になっていた．別の目の批評，2026-11-08）．一つの塊の中で頭の位置を一つにする（ポスターは本文の2字の見出し語で 2.9cm，指標のカードで 2.4cm，提案手法で 6.9cm）．見出し語の後を全角の空白で空けない——語の長さで頭がずれ，続きの行だけ一段深く見える（本人の指摘，2026-11-08）．項目と値の組（入力：，モデル：，正解率：）はコロンで続ける．
- **行は，意味の切れ目で折る．** 数と単位（「10問」），記号と助詞（「𝒉 を」），区間の両端は行で割らない．幅の狭いカードでは，一行ずつ段落を分けて折る位置を決め，自動の折り返しに任せない．
- **補足（注・出典・図の脇の説明）も，本文と同じ基準で書く．** 一文を行の途中で割らず，行ごとに一つのことを言う（写真の出典は「1–3章の写真の出典：GQA[2] の評価データ」「問 … の画像」「加工は本研究による．「別の画像」は説明のための例」の3行．「…の画像は／GQA[2] の評価データ」と文を行で割り，「例示用」のような二通りに読める語で済ませていた）．定義する語で定義しない（「内部表現：…内部で持つベクトル」でなく「…途中で計算するベクトル」），記号には何の値かを添える（ただし式の重み 𝜆 の値は，教授の指摘で外した．2026-11-13），修飾が二つの語に掛からない語順にする（「評価データの質問文と，加工していない画像」），同じ値を二度載せない（12,578問は 3.1 だけ），同じ語を続く行で繰り返さない（「…重みを1回更新」の次の行は「毎回引き直して，これを29,441回繰り返す」で，「更新」を繰り返さない）．補足は読み飛ばされやすいが，読んだ人には本文と同じ重さで読まれる（本人の指摘，2026-11-12）．
- **誤字を残さない．** 用語の揺れ（§1）・送り仮名・変換の誤り・表と本文の数値の不一致を，§6 の1と4で確かめる．

- **ポスターは，学会ポスターの普通の形で組む．** 上に題・著者・所属を置き，本文は段組にし，章ごとに色の付いた見出しや囲みで区切り，書体はゴシックにする．CVPR・ECCV・NeurIPS のポスター7枚と，MIRU2026 の写真3枚で確かめた（2026-11-07）．7枚は 3–4 段組で，MIRU の3枚は題が濃い地に白抜きの全幅の帯だった．明朝の題は見当たらなかった．目立つ独自性より，聴き手が見慣れた形で読めることを取る．
- **教授に送った版から，見た目を不用意に変えない．** 教授に送った版は `tmp/professor/` にあり，いつどの版を送ったかは `tmp/README.md` の一覧にある．組み（区画の位置，色，図の形）を改めるのは，教授か本人が求めたときだけにする．これまでの改めは，求めた指摘とその日付とともに §2–§4 の各項にある．文字を大きくするなど，紙面が要る直しでは，見出しのまわりと図の中の空き，トークンの大きさ，写真の高さから詰め，組みは保つ（教授の5回目の指摘に応えた 2026-11-13 の版）．磨くときは，並べて同じポスターと分かる範囲（書体の太さ，字間，値の色，棒の幅，余白のずれ）に留める——組み直すと，教授が困惑する（本人の指摘，2026-11-07）．
- **図形は，中身が決めた形にする．** 既製の図形を元の比率から大きく伸ばさない（伝わるデザイン）——中身の無い幅は，部品が横に引き伸ばされたように見える．入れ物が横に長くてよいのは，中の部品が連なって幅を埋めるときだけである．ポスターの上限は，中を省いた VLM の枠が写真と同じ 4:3，中を見せる VLM の枠が予稿と同じ 4.3:1，文字の箱が 4:1 とする．中を見せる枠を 3:1 から予稿の比まで広げたのは，予稿と同じく，視覚エンコーダと言語モデル部の囲みで幅が埋まったからである（2026-11-08．それまでは囲みが無く，層のあいだが空いていた）．同じモデルを二度動かす図は，枠を二つに伸ばさず，一つの枠に二つの流れを通す．写真は歪めず 4:3 に揃え，ベクトルのセルは正方形にする．
- **見た目の差は，意味の差として読まれる．** 意味の無い差を作らない（Marshall らの聞き取りに，色の違いで別物と思ったという発言がある）——同じ役目の部品は同じ寸法（答えと正解の箱は 7.5 × 2.2cm）にし，トークンはどこでも同じ大きさの正方形（𝒉 のほかは白．2026-11-13 の版で 0.6cm——VLM の枠の高さから層の名の行を引いた残りに10個を並べる間隔の 0.78倍）にし，VLM の枠と層はどの図でも同じ色と形にする．𝒉 は，VLM の中でも整合損失の枠でも，トークンと同じ大きさの正方形にする（本人の指摘，2026-11-12）．枠の中の手順の別は塗りの濃さで示し（手順 A は基調の緑，手順 B は中間の緑 `8FBF78`），白はトークンにだけ使う——手順 B を白にすると，𝒉 がトークンと同じ見た目になる（同）．枠の注は「正方形：各質問の 𝒉．同じ色は同じ手順」と言う．1章の図はトークンを描かないので，内部表現を取り出す所を緑の丸で示す．矢印の色・太さ・形は意味ごとに一つとし（下の矢印の項），データの流れの矢印は墨の 3pt に留め，部品を覆わない（下の矢印の項）．段を順に並べる矢印は，前の段の文の終わりと次の段の写真のあいだの中央に置く——次の写真に接して置くと不自然に見える（本人の指摘，2026-11-08）．**逆に，意味の違うものを同じ見た目にしない．** 同じ形を一枚の中で二つの意味に使うなら，大きさ・塗り・並べ方・名の四つのうち，できるだけ多くで分ける．ポスターでは，1章の図が一つの内部表現の各次元を，2章の図がトークンを，どちらも正方形で描く．次元のセルは 0.8cm の線のない緑の濃淡で，隙間なく横に12個連ねる．トークンはそれより小さい白地に墨の線で，縦に離して列にし，最初の列の上に「トークン」と名を添える．大きさだけでは見分けにくいので，塗り・並べ方・名でも分ける．𝒉 の正方形だけは，塗りが次元の最も濃いセルと同じ緑になるが，並べ方で分かれる．脇の「内部表現 𝒉」と「ベクトル」の語は，1章のセルの列全体（一つの内部表現）に当たるのが，この正方形一つであることを示す（「1章の図で正方形を並べたものがあるので，これと同じだと思われないようにしたい」本人の指摘，2026-11-12）．
- **一つの部品の塗りと線の両方に色を付けない**（伝わるデザイン）．モデルの入れ物と部品（VLM の枠・視覚エンコーダ・層・出力層）は灰色の地だけにし，線を引かない．入力と出力のデータ（質問文・答え・正解）は白地に線の箱にする——データとモデルを同じ灰にすると，どれがモデルか区別できない（本人の指摘，2026-11-08）．言語モデル部の囲みは灰の線だけで，地を塗らない．写真の縁だけは，白い背景の写真が紙に溶けないよう，淡い灰の 2.25pt を全ての写真に引く．写真の上の緑の枠には，芝の緑に沈まないよう白の縁を付ける．
- **群の色は，資料の中で固定し，資料の基調に合わせる．** baseline は灰色で，スライドは `858585`，ポスターは `A6A6A6`．スライドは proposal が赤 `FF0000`，ablation が水色 `9DC3E6`．ポスターは proposal が基調の緑 `4A8C45`，ablation がその淡い色 `C5E0B4` である．表・グラフ・本文のどこで群を色分けしても，資料の中でこの対応を変えない．色だけで区別させず，凡例か群名を添える（同じ色相の濃淡は，名を添えないと見分けにくい．Datawrapper）．ポスターを緑の濃淡にしたのは，基調の緑に赤（のちに朱）が反対色として当たり，灰・赤・水色・緑・紫と色相が増えて，まとまりが無かったからである（本人の指摘，2026-11-08）．群の差は明度で付ける——緑を明るくしたので灰を淡くして明度を離し，灰と緑は ΔE 19.2（色覚の模擬で 15.2 以上），灰と淡い緑は 16.4（15.3），緑と淡い緑は 30.3（28.5）で，dataviz の下限（15・8）を満たす．ablation は「署名の意味を除いた proposal」なので，proposal の淡い色が意味にも合う．スライドの灰も dataviz の検証で決めた（`A6A6A6` は水色と ΔE 10 で下限に届かないので `858585`）．スライドは白黒の雛形で緑を使わないので，赤と水色のままにする．

- **一般の体裁から外れない．** ゼミのスライドは研究室の雛形（表紙・題の位置・書体・箇条の形）に従う．学会のポスターは，題・著者・所属を上に，本文を段組に，参考文献を末尾に置く．ボード（横 180cm × 縦 90cm）に収まる判（A0 横）にする．

## 5. ファイル——部品を保ち，開き直して確かめる

**既存のファイルは，書式ごと作り直さない．** 直すのは部品（XML）の水準で，文字を差し替えるのを基本とする．組み方そのものを改めるときはスライドの部品を書き直してよいが，グラフ・埋め込みのブック・画像の部品は残し，文の変更は差分で確かめる．

- **python-pptx で書き直さない．** 読む・確かめるのには使ってよい．スライドの追加・削除も部品の水準で行い，`presentation.xml`・その rels・`[Content_Types].xml`・`docProps/app.xml`（枚数と題）を一緒に直す．`app.xml` は `<Slides>`，`HeadingPairs` の題の数，`TitlesOfParts` の `vt:vector size` と実際の要素数の四つを揃える——`size` が要素数と一つ違うだけで PowerPoint は開くのを拒む（0x80070570）が，python-pptx もスキーマの検証もこれを通す．python-pptx が書くと壊れる既知の点——チャートの一つの文字指定に `a:latin` が二つ入る，`c:axId`・`c:crossAx` が負になる——を持ち込まない．
- **作業の経緯をファイルに残さない．** 発表者のメモとコメントにも書かない．文書のプロパティの作成者は本人にする．
- **文字の言語は日本語（`ja-JP`）にし，テーマの東アジアの書体に日本語の書体を当てる．** スライドは研究室の雛形の書体（游明朝・游ゴシック），ポスターは游ゴシックである．

- **書いたら，保存したファイルを開き直して確かめる**（§6）．
- **PDF を本人の環境の外（LibreOffice など）で書き出すときは，日本語の文字に日本語の書体が当たるようにする．** 游明朝・游ゴシックが無い環境では，日本語版の代替（IPAex 明朝・IPAex ゴシックなど）を書体の別名として当てる．PDF は，直した回のうちに最終のファイルから書き出し直す．
